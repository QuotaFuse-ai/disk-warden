# Disk Warden — 功能需求文档

> 版本：v0.1
> 日期：2026-10-16

## 一、产品定位

**一句话**：AI IDE 存储管家——自动识别本机 Cursor/Trae/Claude Code 等 AI 编程工具的数据目录，一键把缓存/索引/日志 junction 到其他盘，让 C 盘不再被吃满。

**跟竞品的区别**：
- CleanMyDev：只删到废纸篓，删完还会涨回来
- 通用 junction 工具（Symlinker 等）：不认识 IDE 目录结构，让用户自己选
- Disk Warden：认识 IDE 目录 + 区分哪些能动哪些不能动 + junction 到目标盘后新数据自动落其他盘

## 二、核心功能

### 2.1 扫描识别（三层策略）

IDE经常改名、改目录，三层并行识别：

| 层 | 做什么 | 说明 |
|---|---|---|
| **第一层：硬编码目录** | 已知IDE的具体路径写死 | Cursor、Trae、Qoder等常见的直接命中，最快 |
| **第二层：规则引擎** | 按子目录名匹配 | 父目录改名了没关系，看里面有Cache/logs/sessions等特征就认出来 |
| **第三层：AI分析** | 不认识的目录调AI判断 | 新出的IDE、规则没覆盖到的，AI判断这是缓存还是配置 |

匹配顺序：硬编码 → 规则引擎 → AI分析 → 都判断不了标黄色让用户自己选

| 功能 | 说明 |
|---|---|
| 自动扫描 `%APPDATA%` 和 `%USERPROFILE%` | 发现已安装的 AI IDE / CLI / 插件 |
| 识别已知 IDE | Cursor、Trae、Windsurf、Kiro、VS Code、Claude Code、Codex、Qoder等 |
| 计算每个子目录大小 | 递归统计，按大小排序 |
| 规则引擎自动分类 | 已知可迁标绿色、不可动标红色、未知标黄色 |
| 检测进程占用 | 发现 IDE 正在运行就警告，不允许迁移 |

### 2.2 迁移（核心）

| 功能 | 说明 |
|---|---|
| 选择目标盘 | D/E/F 下拉 + 自定义路径 |
| 迁移前预览 | 显示"将释放C盘X GB、需要目标盘Y GB、目标盘剩Z GB"，不够就拦住 |
| 迁移前自动备份 | settings.json 等配置备份到 backup/ 目录 |
| 执行迁移 | robocopy 搬数据 → mklink /J 建 junction |
| 预置模式（新用户） | 还没数据时直接建 junction，以后自动写目标盘 |
| 迁移后验证 | 检查 junction 是否成功、IDE 能否正常启动 |

### 2.3 回滚

| 功能 | 说明 |
|---|---|
| 一键迁回 C 盘 | 删 junction → 数据搬回 C 盘原位 |
| 配置恢复 | 从 backup/ 恢复 settings.json |

### 2.4 本地规则学习

| 功能 | 说明 |
|---|---|
| 本地 JSON 存储 | 记录哪些目录迁完没回滚=安全，自动加入绿色列表 |
| 回滚过的目录 | 自动加入红色黑名单，下次不再推荐 |
| 用户手动标记 | 黄色目录用户点"这个安全"或"这个不能动" |
| 不需要联网 | 所有规则存在本地，不上传 |

### 2.5 项目目录扫描

| 功能 | 说明 |
|---|---|
| 扫描已打开的项目 | node_modules、dist/build、.git 各占多大 |
| 按大小排序 | 直接告诉你先清哪个项目 |
| 迁移项目到目标盘 | 搬项目+自动修复 IDE 的 workspaceStorage 映射 |

### 2.6 C 盘全景

| 功能 | 说明 |
|---|---|
| 列出 C 盘大头 | Android SDK、.gradle、Docker、Yarn 缓存等 |
| 不局限于 IDE | 当通用 C 盘瘦身工具用 |

### 2.7 操作历史

| 功能 | 说明 |
|---|---|
| 记录每次操作 | 时间、操作内容、释放了多少空间 |
| 累计释放统计 | 总共帮你腾了多少 G |

### 2.8 自动维护

| 功能 | 说明 |
|---|---|
| 周期性清理 | 每周自动清可再生缓存 |
| 开关 | 用户可手动开关 |

## 三、界面结构

```
顶栏：Logo + 标题 | 自动维护开关 | 重新扫描

概览卡片（4个）：
  C盘剩余 | 目标盘可用 | 可释放总量 | 累计已释放

左侧（4个Tab）：
  [IDE数据] [项目目录] [C盘全景] [规则学习] [操作历史]

右侧详情：
  选中IDE后显示：
    - 路径 + 当前在C盘/已迁D盘标记
    - 进程运行警告（如果IDE开着）
    - 迁移预览卡片（选目标盘、释放多少、空间够不够）
    - 分项列表（每个子目录大小+可再生标记+"以后再生到D盘"按钮）
    - 操作按钮（清理缓存 / 迁移到目标盘 / 预置到目标盘 / 迁回C盘 / 打开目录）
```

## 四、技术方案

| 项目 | 选型 |
|---|---|
| 后端 | Python 3.12 |
| 前端 | 现有 HTML 原型（原生JS） |
| 打包 | PyInstaller（跟 quatofuse 一样，独立exe窗口，不用浏览器） |
| 迁移命令 | Windows: robocopy + mklink /J；Mac: ditto + ln -s |
| 数据存储 | 本地 JSON（规则学习、操作历史） |
| 界面 | 独立exe窗口（内嵌webview），不依赖浏览器 |
| 平台 | Windows版先做，Mac版后续（路径和命令不同，代码分平台处理） |

### 4.1 设置项（右上角设置按钮）

| 设置 | 默认值 | 说明 |
|---|---|---|
| 开机自启 | 关闭 | 用户可开，开机后托盘后台运行 |
| 目标存储根目录 | `D:\DiskWarden\`（Windows）/ `~/DiskWarden/`（Mac） | 用户可改成任意盘符/目录 |
| 卸载时行为 | 用户预设 | 提前设好：自动迁回C盘 / 保留当前位置不动 |
| 语言 | 英文（GitHub开源版默认） | 可切中文；语言包是独立JSON文件，加新语言就加个文件 |
| 自动维护 | 关闭 | 每周自动清可再生缓存 |

### 4.2 根目录结构

第一次运行后在用户设置的盘符下创建：

```
D:\DiskWarden\                  ← 根目录（用户自定义）
├── data\                      ← 迁移过来的数据，按软件名分
│   ├── Cursor\
│   ├── TraeCN\
│   └── ...
├── backup\                    ← 配置备份，按日期+软件名分
│   └── 2026-10-16_Cursor\
├── logs\                      ← 操作日志，按日期
│   └── 2026-10-16.log
└── config\                    ← 软件自己的配置
    ├── settings.json           ← 用户设置
    ├── rules-learned.json      ← 本地规则学习
    ├── history.json            ← 操作历史
    └── locales\               ← 语言包（i18n）
        ├── en.json             ← 英文（默认）
        ├── zh-CN.json           ← 中文
        └── ...                  ← 加新语言就加个新JSON文件
```

### 4.4 反馈与诊断

| 功能 | 说明 |
|---|---|
| "报告问题"按钮 | 点击跳转到 GitHub Issues 页面 |
| 自动诊断信息 | 生成诊断文本（本机扫到的IDE、各目录大小、迁移记录、操作系统版本），用户复制粘贴到Issue里 |
| Issue入口 | GitHub Issues模板里加"一键生成诊断信息"入口，方便用户提交 |

### 4.5 GitHub/Gitee登录+Star引导

| 功能 | 说明 |
|---|---|
| 启动欢迎页 | 打开软件先弹一个欢迎页，不是主界面 |
| GitHub登录并Star按钮 | 大按钮，主色调，引导用户点（海外用户） |
| Gitee登录并Star按钮 | 大按钮，主色调，引导用户点（国内用户） |
| 跳过按钮 | 极小、灰色、右下角，几乎看不见 |
| GitHub OAuth | 用户授权后自动检查是否star了仓库 |
| Gitee OAuth | 用户授权后自动检查是否star了仓库 |
| 没star | 自动跳转到仓库页面让他点 |
| 已star | 进入主界面 |
| 不需要服务器 | 本地临时HTTP接收回调，纯Python实现 |

**登录后点星引导逻辑（重要）**：
- 登录成功后**直接进入主界面**，不是卡在登录页
- 主界面上面弹一层**半透明蒙版**+小弹窗（点星引导）
- **根据登录平台判断**：
  - 用户用GitHub登录 → 点星引导按钮调用GitHub API给GitHub仓库加star
  - 用户用Gitee登录 → 点星引导按钮调用Gitee API给Gitee仓库加star
- 点Star按钮成功 → 蒙版消失，继续用主界面
- 点"跳过" → 蒙版消失，继续用主界面
- 不强制，可跳过

### 4.3 云端规则同步（后续版本）

服务器上两个文件：

| 文件 | 作用 | 谁能改 |
|---|---|---|
| `rules.json`（静态） | 最新的可迁/不可动目录规则，客户端启动时拉一下 | 开发维护 |
| `feedback.json`（可编辑） | 官方人员/社区直接标记"这个目录有问题别迁"或"这个目录可以迁" | 官方维护 |

客户端逻辑：本地规则 + 云端规则合并，云端标红的目录优先警告用户。

## 五、安全注意事项（必须遵守）

### 5.1 文件被占用检测
- 迁移前检测对应IDE进程是否在运行
- 如果IDE开着，弹窗警告"请先关闭Cursor再迁移"，不允许开始迁移
- 不强制杀进程，让用户自己关

### 5.2 迁移后验证
- robocopy搬完后，自动对比源目录和目标目录的文件数量、总大小
- 验证通过才删C盘原目录、建junction
- 验证不通过：不动C盘原目录，报错让用户重试
- 验证结果显示给用户："验证通过，已释放C盘XX GB"或"验证失败，数据未动"
- 搬移过程显示进度条（当前文件、百分比）

### 5.3 配置备份
- 只备份配置文件（settings.json等，几KB），不备份数据本身
- 备份存到 `D:\DiskWarden\backup\日期_软件名\` 下
- 迁移出问题时可从备份恢复配置

### 5.4 不自动动红色目录
- 红色标记（登录凭证、配置、记忆）绝对不自动碰
- 黄色标记（未知目录）必须用户手动确认才能操作
- 宁可保守，不能误删
