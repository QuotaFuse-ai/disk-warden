## 0. 结论摘要

1. **第一期（P0）只做一条主链路**：扫描 → 规则判定 → 迁移计划 → 配置备份 → 复制校验 → 建链 → 验证 → 回滚。其余五个模块不进入 P0。
2. **8 个模块全部完成优先级标注**：扫描、迁移、回滚为 P0；规则学习、项目目录、C 盘全景、操作历史为 P1；自动维护为 P2（决策 0001 未明确列入 P1，按"可延后"归档，需人类确认）。
3. **每个 P0 模块都有条目化验收标准**，统一按"输入/前置、用户动作、预期输出、异常分支"四段描述，并给出可复现的测试场景。
4. **破坏性操作的安全口径已统一**：校验不通过不动源数据；迁移/回滚任意时刻至少保留一份完整可读数据；失败与中断必须落到明确状态；任何不确定情况交给用户，不自动删除。
5. **五个必须覆盖的异常全部有验收项**：进程占用、目标盘空间不足、权限不足、迁移中断、回滚失败。
6. **不扩大第一期范围**：第三层 AI 分析、预置模式、项目目录迁移、自动清理、云端规则同步均不在 P0；无法确认的实现细节统一登记为"待确认"，不臆造。

## 1. 产品定位、目标与原则

### 1.1 一句话定位

Disk Warden 是面向 Windows 开发者的 **AI IDE 存储管家**：识别 Cursor、Trae、Claude Code 等工具的数据目录，把可再生数据安全迁移到其他磁盘，原路径保持可用，并提供一键回滚。

### 1.2 目标用户与典型场景

**目标用户**

- Windows 10/11 的开发者，使用 1~3 个 AI IDE/CLI。
- 系统盘容量有限（常见 256 GB / 512 GB），C 盘长期告急。
- 不具备判断"哪些目录能删、哪些不能动"的能力，担心误删登录凭证或项目数据。

**典型场景**

1. 用户发现 C 盘只剩 8 GB，打开 Disk Warden。
2. 扫描后看到 Cursor 的数据目录占 42 GB，其中大部分是缓存、会话和工作区索引。
3. 用户选择目标盘 D（剩余 300 GB），预览到"释放 42 GB，目标盘需要 44 GB"。
4. 用户确认后执行迁移；界面显示进度；完成后原路径仍可打开，新产生的数据自动写到 D 盘。
5. 用户打开 IDE，历史会话、项目索引正常；如出现异常，可一键迁回 C 盘。

### 1.3 P0 产品目标（可衡量）

1. 在**沙箱目录**中完成一次"扫描 → 迁移 → 验证 → 回滚"闭环，前后数据零丢失。
2. 能识别 `docs/目录清单.md` 已结构化的已知工具及其数据根，并按红/黄/绿给出分类。
3. 用户能在不明白文件系统原理的情况下，独立完成一次迁移，且能看懂"释放多少、目标够不够、为什么不能迁移"。
4. 迁移失败或中断后，用户能明确知道"数据现在在哪、是否安全、下一步做什么"。
5. 全程不需要管理员权限，不需要联网，不上传任何扫描或迁移数据。

### 1.4 非目标（本期明确不做）

- 不做账号系统、云同步、遥测、支付、论坛、邀请返利。
- 不删除用户个人文件，不做"清理缓存"式的直接删除（原型上的该入口见待确认 Q6）。
- 不动登录凭证、配置、记忆类目录（红色条目）。
- 不做杀毒、系统优化、驱动管理。
- P0 不做 Mac 版、不做自动更新、不做云端规则同步。
- P0 不做第三层"AI 分析未知目录"。
- P0 不迁移项目目录，不修复项目工作区映射。
- P0 不自动启动 IDE 做验证（见待确认 Q4）。

### 1.5 产品原则与安全不变量

**优先级**：数据正确性与可回滚性 > 用户可理解 > 简单 > 界面表现。

**任何实现不得违反的安全不变量**

1. **源数据在校验通过前只读**：复制阶段不修改源目录。
2. **校验不通过绝不删除源数据**：文件数、总字节、相对路径集合任一不一致即失败。
3. **建链并验证成功前，不把源数据视为可清理**。
4. **回滚与迁移对称**：先复制、再校验、最后才清理目标侧。
5. **任意时刻至少保留一份完整可读的数据副本**；最坏情况是"两份副本"，绝不是"没有数据"。
6. **不跟随目录链接做递归统计、复制或删除**，避免重复计算与循环。
7. **红色条目任何情况下不可迁移、不可删除**；黄色条目必须逐条显式确认。
8. **不请求管理员权限**；权限不足时停止并解释，不绕过系统权限。
9. **删除只针对本次任务明确记录、明确命名的路径**，不使用通配符删除父目录。
10. **不确定时停下来**：状态或文件系统观测不足以判断时，标记"需人工处理"，不自动清理。

## 3. 术语与全局口径

### 3.1 术语

| 术语 | 定义 |
|---|---|
| 工具 | 一个 AI IDE、CLI 或插件，例如 Cursor、Trae CN、Claude Code。 |
| 数据根 | 某工具在磁盘上的顶层数据目录，例如 `%APPDATA%\Cursor`、`%USERPROFILE%\.claude`。同一工具可同时存在新旧多个数据根。 |
| 条目 | 扫描结果中一个可独立处理的数据单元，通常是一个子目录，也可是单个文件（如 SQLite 数据库）。 |
| 迁移 | 把条目数据复制到目标盘，原路径改为目录链接；用户仍从原路径访问。 |
| 目录链接 | Windows 的 junction：原路径指向目标目录的重解析点。删除链接不影响目标数据。 |
| 目标根目录 | 迁移数据的存放根目录，默认 `D:\DiskWarden\`，用户可修改。 |
| 回滚 | 把已迁移条目的数据迁回 C 盘原位置，删除目录链接。 |
| 扫描快照 | 一次扫描得到的工具、条目、大小、分类、进程状态的结果集合。 |
| 已迁移 | 条目原路径已是有效目录链接，且指向本产品记录的目标位置。 |
| 沙箱 | 测试专用的临时目录，模拟 `%APPDATA%` 结构；验收不得使用真实用户目录。 |
| 红色 / 黄色 / 绿色 | 不可动 / 未知需确认 / 可迁移，定义见 3.3。 |
| 数据零丢失 | 迁移或回滚的任意时刻，数据至少存在一份完整可读副本；完成后用户可从预期路径访问。 |
| 校验通过 | 源与目标的相对路径集合一致、文件数一致、每个文件大小一致、总字节一致。P0 不做全量内容哈希。 |

### 3.2 空间、时间与显示口径

- **需求量** = `数据字节数 × 1.05 + 64 MiB`（向上取整）。5% 与 64 MiB 是为文件系统开销和并发写入预留的安全余量。
- **空间判断**：目标可用空间 < 需求量 → 阻断。预览显示"将释放 / 需要 / 目标剩余"三项；数字以字节为准，显示允许四舍五入。
- **显示单位**：采用 1024 进制，界面文案使用 GB；验收以实际字节数为准，显示误差不超过 0.1 GB。
- **排序**：条目按大小降序；大小相同时按名称升序。
- **时间**：操作日志与历史使用本地时区展示，存储使用 ISO 8601；正确性判断不依赖时间。
- **进度**：迁移与回滚显示当前阶段、已处理字节/文件数、总字节/文件数；不承诺精确剩余时间。

### 3.3 安全等级与条目状态

**安全等级（由规则判定，用户不可把红色改为可迁移）**

| 等级 | 含义 | 用户可执行的操作 |
|---|---|---|
| 绿色 | 已知可再生数据（缓存、日志、会话、索引等） | 可直接选择迁移 |
| 黄色 | 未知目录，规则无法判断 | 必须逐条勾选"我确认此目录可迁移"后才能进入本次计划；确认仅对本次计划有效 |
| 红色 | 登录凭证、配置、记忆等不可动数据 | 不可选择、不可迁移、不可删除；界面说明原因 |

**条目状态**

| 状态 | 含义 |
|---|---|
| 未迁移 | 原路径是普通目录/文件 |
| 迁移中 | 有进行中的迁移任务 |
| 已迁移 | 原路径是有效目录链接，指向记录的目标 |
| 链接失效 | 原路径是链接，但目标不存在或指向不符 |
| 回滚中 | 有进行中的回滚任务 |
| 已回滚 | 原路径恢复为普通目录，目标侧数据已按规则清理 |
| 失败 | 最近一次操作失败，数据仍在至少一侧 |
| 恢复待处理 | 检测到中断残留，自动恢复证据不足，需要用户或人工介入 |

### 3.4 通用交互规则

1. **破坏性操作必须二次确认**：确认页展示条目、目标、释放量、需求量、阻断项；用户主动点击"开始迁移/开始回滚"才执行。
2. **确认与计划绑定**：预览生成后 5 分钟内有效；超时、目标变化或条目变化需重新预览。
3. **阻断优先于警告**：存在阻断项时执行按钮不可用，并逐条说明原因；警告不阻断但必须可见。
4. **错误提示必须回答三件事**：发生了什么、数据现在是否安全、用户下一步做什么。禁止只显示错误码。
5. **只允许一个写任务**：同一时刻最多一个迁移或回滚任务；扫描与写任务互斥。重复触发时提示"已有任务在进行"。
6. **应用退出保护**：有进行中的写任务时拦截退出并提示；用户强制退出后由中断恢复机制兜底。
7. **不请求提权**：全程普通用户权限。
8. **离线**：扫描、迁移、回滚不发起网络请求。

## 4. P0 模块规格与验收标准

> 验收编号规则：`AC-<模块>-<序号>`。每个验收项都可以在沙箱中复现；"预期输出"同时包含界面表现与文件系统结果。

### 4.1 M1 扫描识别（P0）

#### 4.1.1 目标与范围

识别本机已安装的 AI IDE/CLI，列出其数据根与条目，统计大小，完成红黄绿分类，并检测工具进程是否在运行。P0 只做"硬编码识别 + 名称/特征规则"两层，不做 AI 分析。

#### 4.1.2 功能条目

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1.1 | 启动扫描与手动重扫 | P0 | 首次进入主界面自动扫描一次；顶栏"重新扫描"可手动触发 |
| F1.2 | 已知工具识别 | P0 | 按硬编码数据根识别；同一工具的新旧目录合并展示（如 Trae CN / TRAE SOLO CN） |
| F1.3 | 条目枚举与大小统计 | P0 | 递归统计字节数与文件数；不跟随目录链接；权限错误计数并继续 |
| F1.4 | 红黄绿分类 | P0 | 优先级：规则数据精确命中 → 名称/特征规则 → 未知黄色 |
| F1.5 | 进程占用检测 | P0 | 按工具检测进程；运行中则标记并阻断该工具的迁移 |
| F1.6 | 已迁移状态识别 | P0 | 原路径是有效链接时显示"已迁移"及目标位置；链接失效时告警 |
| F1.7 | 进度、取消与空态 | P0 | 扫描可取消；无工具、部分失败、全部失败均有明确界面 |
| F1.8 | 第三层 AI 分析未知目录 | P2 | 本期不实现；是否实现取决于人类确认（见待确认 Q2） |

#### 4.1.3 验收标准

##### AC-SCAN-01 首次扫描发现已安装工具

- **输入/前置**：沙箱中存在 Cursor 与 Claude Code 的数据根；存在一个未安装工具的已知路径（不存在）。
- **用户动作**：首次进入主界面（自动扫描），或点击"重新扫描"。
- **预期输出**：列表中出现 Cursor、Claude Code；未安装的工具不出现；每个工具显示名称、数据根数量、条目数、总大小；不存在的路径只记入扫描警告，不影响其他工具。
- **异常分支**：扫描根不存在 → 跳过并显示"部分位置不可用"警告；扫描过程异常 → 展示失败原因与"重试"，保留上一次成功结果。

##### AC-SCAN-02 新旧目录并存时合并识别

- **输入/前置**：同一工具同时存在旧目录与新目录（如 `Trae CN` 与 `TRAE SOLO CN`）。
- **用户动作**：执行扫描。
- **预期输出**：展示为一个工具、多个数据根；条目列表不重复；同一相对路径只出现一次；缺失其中一个目录时仍展示另一个。
- **异常分支**：两个目录内容冲突（同一相对路径同时存在）→ 分别展示并标注来源根，不自动合并大小。

##### AC-SCAN-03 大小统计准确且可解释

- **输入/前置**：沙箱工具目录包含 1,000 个文件、已知总字节数；其中 1 个子目录当前用户不可读。
- **用户动作**：执行扫描。
- **预期输出**：可读部分的总字节与文件数与实际一致；不可读子目录被计入警告，该条目大小标记为"≥ 已统计值"；扫描正常完成，按大小降序排列。
- **异常分支**：文件在统计过程中被修改或删除 → 以最终可读到的结果为准，并标记该条目"扫描结果可能不完整"；不中断整个扫描。

##### AC-SCAN-04 不跟随目录链接

- **输入/前置**：工具目录下存在一个指向外部大目录的目录链接。
- **用户动作**：执行扫描。
- **预期输出**：链接本身被识别为"已迁移/链接"状态；不进入链接目标统计；总大小不重复计算；扫描不出现循环或卡死。
- **异常分支**：链接目标不存在 → 标记"链接失效"并告警；仍不进入目标、不自动修复。

##### AC-SCAN-05 红黄绿分类符合规则

- **输入/前置**：条目分别命中规则数据中的绿色（如 `Cache`）、红色（如 `settings.json`、`Login Data`）、未命中任何规则的未知目录。
- **用户动作**：查看扫描结果并尝试选择条目。
- **预期输出**：绿色可勾选；黄色显示"需确认"，默认不勾选，勾选时要求逐条确认；红色不可勾选，并显示不可动原因；分类原因对用户可见。
- **异常分支**：规则数据缺失或损坏 → 不得把所有条目默认成绿色；按"未知黄色"处理并提示规则数据异常（见 AC-STORE-03）。

##### AC-SCAN-06 进程占用检测与拦截

- **输入/前置**：沙箱对应工具的模拟进程正在运行。
- **用户动作**：执行扫描，尝试选择该工具条目。
- **预期输出**：工具与条目显示"运行中"；迁移入口不可用，并提示"请先关闭该工具后再迁移"；扫描本身正常完成；不主动结束进程。
- **异常分支**：无法确认进程状态（检测失败）→ 标记"状态未知"，迁移计划阶段阻断，要求用户关闭工具后重试；不得按"未运行"放行。

##### AC-SCAN-07 扫描进度、取消与重复触发

- **输入/前置**：包含大量文件的工具目录。
- **用户动作**：扫描中点击"取消"；再次点击"重新扫描"。
- **预期输出**：取消后 1 秒内进入"已取消"状态，界面保留上一次成功结果，不展示半成品数据；扫描期间"重新扫描"不可重复启动或提示"正在扫描"；界面全程可响应。
- **异常分支**：取消时恰好完成 → 以完成结果为准，并提示"扫描已完成"；单个工具统计出错 → 该工具标记失败，其他工具继续。

##### AC-SCAN-08 空态与部分失败

- **输入/前置**：场景 A：本机没有任何受支持工具；场景 B：所有扫描根均不可访问。
- **用户动作**：执行扫描。
- **预期输出**：场景 A 展示空态，说明支持的工具类别与"重新扫描"入口；场景 B 展示失败原因、涉及路径与"重试"；两种场景都不显示虚假数据。
- **异常分支**：只有部分根不可访问 → 展示已发现结果，并在顶部显示可展开的警告列表。

##### AC-SCAN-09 已迁移与链接失效状态

- **输入/前置**：场景 A：条目原路径是指向有效目标的目录链接；场景 B：链接目标被删除或盘符掉线。
- **用户动作**：执行扫描。
- **预期输出**：场景 A 显示"已迁移至 `<目标路径>`"，不再计入 C 盘可释放量，提供"迁回 C 盘"入口；场景 B 显示"链接失效"高风险告警，提供回滚/修复说明，不自动删除或重建链接。
- **异常分支**：链接指向非本产品记录的目录 → 标记"非本产品创建的链接"，不提供自动回滚，提示用户确认来源。

#### 4.1.4 边界与不做

- P0 不主动发现规则数据之外的未知工具，不做 AI 判断。
- P0 不扫描项目目录（P1）、不做 C 盘全景（P1）。
- 扫描只读，不修改任何文件。
- 不承诺扫描速度作为阻断性验收；参考目标见 9.4。

### 4.2 M2 迁移（P0）

#### 4.2.1 目标与范围

把用户选中的绿色条目（或已确认的黄色条目）迁移到目标盘，原路径保持可访问，新产生的数据写入目标盘；全过程可预览、可追踪、可取消（关键窗口除外），失败不损坏数据。

#### 4.2.2 功能条目

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F2.1 | 选择目标根目录 | P0 | 默认 `D:\DiskWarden\`；可从可用磁盘中选择或自定义路径 |
| F2.2 | 迁移计划预览 | P0 | 展示条目、释放量、需求量、目标剩余、阻断项与警告 |
| F2.3 | 空间与前置校验 | P0 | 空间、目标卷能力、红色/黄色、进程、路径、源状态、长路径 |
| F2.4 | 二次确认 | P0 | 用户主动确认才执行；确认与计划绑定、5 分钟有效 |
| F2.5 | 配置备份 | P0 | 迁移前备份配置文件（KB 级），生成清单；备份失败即中止 |
| F2.6 | 复制与校验 | P0 | 复制数据；按路径集合、文件数、每文件大小、总字节校验 |
| F2.7 | 建链与验证 | P0 | 原路径创建目录链接；验证链接目标与数据可读 |
| F2.8 | 进度、取消与结果汇总 | P0 | 显示阶段与字节/文件进度；可取消；逐条给出结果 |
| F2.9 | 单条目与多条目批量迁移 | P0 | 条目级原子；批量中单项失败不影响已完成项 |
| F2.10 | 迁移后使用验证 | P0（人工） | 沙箱中由验收人打开 IDE 确认数据可用；自动启动 IDE 验证待确认 Q4 |
| F2.11 | 预置模式（无数据时直接建链） | P1 | 决策 0001 的 P0 未列，本规格归 P1，避免扩大第一期范围 |

#### 4.2.3 验收标准

##### AC-MIG-01 单条目迁移成功

- **输入/前置**：沙箱中一个绿色条目，数据 2.0 GiB；目标盘剩余 50 GiB；对应工具已关闭；目标根可写。
- **用户动作**：勾选条目 → 选择目标根 → 点击"迁移" → 查看预览 → 点击"开始迁移"。
- **预期输出**：预览显示释放约 2.0 GB、需要约 2.1 GB、迁移后剩余约 47.9 GB；执行过程显示复制、校验、建链、验证阶段；完成后提示"迁移成功，已释放约 2.0 GB"；原路径可打开且为有效目录链接；目标侧相对路径、文件数、总字节与源一致；条目状态变为"已迁移"；历史新增一条成功记录。
- **异常分支**：任一阶段失败 → 按 AC-MIG-06/08/09 处理，源数据保持完整，不得出现"原路径打不开且数据不在目标"的状态。

##### AC-MIG-02 目标盘空间不足

- **输入/前置**：目标可用空间小于"数据量 × 1.05 + 64 MiB"。
- **用户动作**：生成迁移预览。
- **预期输出**：显示为阻断项，列出"需要 / 可用 / 缺口"；"开始迁移"不可用；源与目标均未发生任何写入；用户可更换目标后重新预览。
- **异常分支**：预览后目标空间被其他程序占用，执行前复核发现不足 → 在修改任何数据前中止，提示重新选择目标。

##### AC-MIG-03 目标位置不可用或不支持

- **输入/前置**：目标路径不存在、不可写、盘符掉线、位于源目录内部、为网络盘、文件系统不支持目录链接（如 exFAT/FAT32），或为只读卷。
- **用户动作**：生成迁移预览。
- **预期输出**：分别给出可理解的阻断原因（不是统一报"失败"）；不写入任何一侧；目标路径位于源目录内部时必须阻断并解释。
- **异常分支**：执行中目标盘掉线 → 中止任务，源保持完整，目标侧残留按 AC-MIG-06 的清理规则处理；可移动磁盘作为目标根在 P0 默认阻断（待确认 Q8）。

##### AC-MIG-04 进程占用拦截

- **输入/前置**：场景 A：预览时工具进程在运行；场景 B：复制过程中用户启动了该工具。
- **用户动作**：生成预览 / 开始迁移。
- **预期输出**：场景 A 在预览中标为阻断，不能开始；场景 B 在进入任何破坏性步骤前中止，提示"检测到工具已启动，迁移已停止"；源数据不变；不创建目录链接；条目仍为"未迁移"，可在关闭工具后重试。
- **异常分支**：无法确认进程状态 → 按阻断处理（宁可失败，不可误操作）；中止后临时副本清理失败 → 记录位置并提示，不触碰源数据。

##### AC-MIG-05 权限不足

- **输入/前置**：源目录中部分文件被占用或 ACL 拒绝读取；或目标目录拒绝写入。
- **用户动作**：生成预览并开始迁移。
- **预期输出**：预览阶段能发现的目标不可写应提前阻断；复制阶段遇到权限错误立即中止，提示具体路径与"文件可能被占用或权限不足"；源数据不被修改；不创建目录链接；不请求管理员权限。
- **异常分支**：已复制的临时数据因权限无法清理 → 保留并记录路径，标记"清理待处理"；源数据不受影响。

##### AC-MIG-06 复制校验失败

- **输入/前置**：注入校验失败（文件数、单文件大小或总字节不一致）。
- **用户动作**：执行迁移。
- **预期输出**：提示"迁移失败，C 盘数据未动"；不创建目录链接；条目仍为"未迁移"；目标侧不完整副本标记为本次任务产生，尽力清理；历史记录失败原因（失败阶段、期望值与实际值）；可重试。
- **异常分支**：清理不完整副本失败 → 保留并记录，不删除源数据；用户可看到残留位置。

##### AC-MIG-07 迁移中断恢复

- **输入/前置**：在以下阶段分别强制结束应用或断电：复制前、复制中、复制完成未建链、源目录换位后未建链、建链后未验证。
- **用户动作**：重新启动应用。
- **预期输出**：启动时识别到未完成任务，显示"检测到未完成的迁移"及任务信息；按证据自动恢复为明确结果之一：迁移完成（链接有效、数据完整）、已恢复为未迁移（源数据完整）、或"需人工处理"；任何情况下至少一份完整数据可读；历史/日志记录恢复动作；不重复出现同一任务。
- **异常分支**：状态与文件系统观测矛盾（如源路径、目标、临时数据均不存在）→ 停止自动操作，标记"恢复待处理"，展示诊断信息与人工步骤；不得猜测性删除。

##### AC-MIG-08 建链或链接验证失败

- **输入/前置**：注入链接创建失败，或链接创建成功但读回目标不符。
- **用户动作**：执行迁移。
- **预期输出**：迁移失败；源数据恢复到原路径且可读；不留下失效链接；目标侧数据保留或按规则清理，但不得删除唯一副本；条目状态为"未迁移"或"失败"，可重试。
- **异常分支**：恢复源路径失败 → 标记"恢复待处理"，保留两侧数据，停止自动操作并提示人工介入。

##### AC-MIG-09 用户取消

- **输入/前置**：复制阶段执行取消；以及进入关键换位窗口后尝试取消。
- **用户动作**：点击"取消"。
- **预期输出**：复制阶段 3 秒内停止，源数据不变，临时副本清理，条目为"未迁移"，提示"已取消，数据未变动"；进入关键换位窗口后取消按钮不可用，提示"正在完成关键步骤，请稍候"；窗口结束后给出最终结果。
- **异常分支**：取消与完成同时发生 → 以实际文件系统结果为准，明确提示"任务已完成/已取消"，不得显示矛盾状态。

##### AC-MIG-10 多条目批量迁移

- **输入/前置**：勾选同一工具或多个工具的多个条目；其中 1 条被进程/红色/空间条件阻断。
- **用户动作**：生成预览并确认执行。
- **预期输出**：预览显示汇总与逐条阻断；默认不执行阻断项，其余条目可执行；每个条目独立原子；结果清单逐条列出成功/失败/跳过及原因；已完成条目不因后续条目失败而回滚。
- **异常分支**：批量执行中取消 → 已完成条目保持已迁移，当前条目按 AC-MIG-09 恢复，未开始条目保持未迁移；中断恢复按任务逐条判断。

##### AC-MIG-11 重复迁移与并发操作

- **输入/前置**：条目已迁移；或在有写任务进行时再次发起迁移。
- **用户动作**：尝试再次迁移 / 发起第二个任务。
- **预期输出**：已迁移条目不可再次迁移，只提供回滚；链接失效时不提供"重新迁移"，先要求回滚或修复；已有写任务时提示"已有任务在进行"，不启动第二个任务。
- **异常分支**：两个入口同时提交（界面快速双击）→ 只接受一个任务，另一个明确提示未执行。

##### AC-MIG-12 长路径与超长目标路径

- **输入/前置**：源路径或目标路径中任一侧超过 240 个字符。
- **用户动作**：生成迁移预览。
- **预期输出**：阻断并指出具体条目；建议选择更短的目标根目录；不进行任何写入；不出现"复制到一半才因路径失败"。
- **异常分支**：复制过程中才暴露路径问题 → 中止并按 AC-MIG-06 处理，源数据不变。

##### AC-MIG-13 迁移后使用验证

- **输入/前置**：AC-MIG-01 成功后的沙箱条目。
- **用户动作**：打开对应工具，访问历史会话/索引；在工具中产生少量新数据；查看目标目录。
- **预期输出**：工具可正常启动并读取迁移前数据；新产生的数据出现在目标盘；原路径仍可访问；不需要重新登录（红色配置未被移动）。
- **异常分支**：工具报数据缺失或异常 → 提供"一键迁回 C 盘"入口；不自动修改 IDE 配置或数据；记录为验收失败并附带日志。

#### 4.2.4 边界与不做

- P0 不做预置模式（P1）。
- P0 不迁移项目目录。
- P0 不做"清理缓存"直接删除。
- P0 不自动启动 IDE 验证（待确认 Q4）。
- P0 不支持可移动磁盘作为目标根（默认阻断，待确认 Q8）。

### 4.3 M3 回滚（P0）

#### 4.3.1 目标与范围

把已迁移条目的数据从目标盘迁回 C 盘原位置，恢复为普通目录，并按安全规则处理配置，最终让工具回到迁移前状态。

#### 4.3.2 功能条目

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F3.1 | 回滚入口与预览 | P0 | 从已迁移条目发起；预览显示需回迁数据量、C 盘需求量、目标位置 |
| F3.2 | 回滚前置校验 | P0 | 链接有效、目标可用、C 盘空间足够、源路径状态符合预期 |
| F3.3 | 数据回迁与校验 | P0 | 复制回 C 盘，按与迁移相同的口径校验 |
| F3.4 | 配置恢复 | P0 | 仅备份未移动配置；按"缺失才恢复、变更需确认"的规则处理 |
| F3.5 | 回滚失败保护 | P0 | 失败时保留两侧数据，不删除任一侧，转人工处理 |
| F3.6 | 回滚中断恢复 | P0 | 重启后识别未完成回滚并恢复为明确状态 |
| F3.7 | 批量回滚与结果汇总 | P0 | 条目级原子，逐条结果 |
| F3.8 | 回滚历史与状态 | P0 | 写入历史，条目状态更新为"已回滚" |
| F3.9 | 回滚后自动加入红色规则 | P1 | 随规则学习模块实现；P0 只记录历史 |

#### 4.3.3 验收标准

##### AC-ROL-01 单条目回滚成功

- **输入/前置**：AC-MIG-01 后的已迁移条目；链接有效；目标盘在线；C 盘空间充足；工具已关闭。
- **用户动作**：点击"迁回 C 盘" → 查看预览 → 确认。
- **预期输出**：删除链接后数据复制回原路径并校验通过；原路径变为普通目录且可读；目标侧数据在回迁成功并校验后才清理；C 盘可用空间相应减少、目标盘可用空间相应增加；条目状态"未迁移"；历史新增"已回滚"记录。
- **异常分支**：任一阶段失败 → 按 AC-ROL-03/04 处理，至少保留一份完整数据。

##### AC-ROL-02 回滚空间不足

- **输入/前置**：C 盘可用空间小于回迁需求量。
- **用户动作**：生成回滚预览。
- **预期输出**：阻断，显示需要/可用/缺口；目录链接保持原样，数据仍可访问；不进行任何写入；用户清理空间后可重试。
- **异常分支**：预览后空间变化 → 执行前复核，不足则在修改前中止。

##### AC-ROL-03 回滚失败

- **输入/前置**：注入复制失败、校验失败或权限不足（任选其一）。
- **用户动作**：执行回滚。
- **预期输出**：提示"回滚失败，数据已保留"；明确告知数据当前在源路径链接/目标路径中的哪一侧可访问；**不删除任何一侧数据**；提供重试与诊断信息；条目状态为"失败"或"已迁移"，不得显示"已回滚"。
- **异常分支**：清理链接失败或恢复源路径失败 → 标记"恢复待处理"，停止自动操作，保留两侧数据并给出人工步骤。

##### AC-ROL-04 回滚中断恢复

- **输入/前置**：在回滚的复制中、校验中、清理目标前分别强制结束应用或断电。
- **用户动作**：重新启动应用。
- **预期输出**：识别未完成回滚；按证据恢复为"已回滚"或"保持已迁移"之一；数据至少一份完整可读；清理目标只在确认源侧完整后执行；历史/日志记录恢复动作。
- **异常分支**：证据不足（源路径、目标、临时数据状态互相矛盾）→ 标记"恢复待处理"，不自动删除，展示诊断与人工步骤。

##### AC-ROL-05 目标盘不可用

- **输入/前置**：已迁移条目的目标盘掉线或目标目录不存在。
- **用户动作**：发起回滚。
- **预期输出**：阻断并提示"目标盘不可用，暂时无法回滚"；不删除链接、不修改数据；目标盘恢复后可重试；若链接已失效，按 AC-SCAN-09 显示"链接失效"并提供恢复说明。
- **异常分支**：用户坚持操作 → 仍不执行，避免把可恢复状态变成不可恢复状态。

##### AC-ROL-06 配置恢复语义

- **输入/前置**：场景 A：迁移时的配置备份存在，当前配置与备份一致；场景 B：当前配置文件缺失；场景 C：当前配置在迁移后被用户修改；场景 D：备份缺失或损坏。
- **用户动作**：执行回滚。
- **预期输出**：场景 A 不覆盖当前配置；场景 B 自动从备份恢复并记录；场景 C 弹窗让用户选择"保留当前配置（默认）"或"恢复迁移时备份"，不静默覆盖；场景 D 数据回滚照常完成，配置恢复标记为"未恢复"并列出受影响文件。
- **异常分支**：配置恢复写入失败 → 数据回滚结果不受影响，配置项标记失败并提示，不删除现有配置。

##### AC-ROL-07 批量回滚

- **输入/前置**：多个已迁移条目，其中一个目标盘不可用或空间不足。
- **用户动作**：批量回滚。
- **预期输出**：预览逐条显示可执行/阻断；阻断项与可执行项分开；每个条目独立原子；结果逐条列出成功/失败/跳过；成功条目不因其他条目失败而回退。
- **异常分支**：批量中取消或中断 → 已完成条目保持已回滚，当前条目按 AC-ROL-04 恢复，其余保持已迁移。

##### AC-ROL-08 重复回滚与已回滚状态

- **输入/前置**：条目已经回滚（原路径为普通目录，目标侧已清理）。
- **用户动作**：再次尝试回滚。
- **预期输出**：提示"该条目已回滚"，不执行任何操作；若原路径为普通目录但目标侧仍有残留副本，标记"残留副本"并提示用户确认后再处理，不自动删除。
- **异常分支**：原路径是普通目录但链接记录仍存在 → 以实际文件系统为准，标记状态异常并记录，不自动清理任一侧。

#### 4.3.4 边界与不做

- P0 不做定时回滚、不做跨设备回滚。
- P0 不自动删除回滚后目标侧的残留副本；清理需用户确认。
- P0 不把回滚结果自动写入规则学习（P1 实现自动红色）。

## 5. P0 支撑能力规格

### 5.1 本地设置与数据（P0）

**存放位置**：目标根目录下的配置目录（默认 `D:\DiskWarden\config\`），具体文件名沿用需求文档 §4.2。

**P0 必须存在的数据**

| 数据 | 作用 | P0 要求 |
|---|---|---|
| `settings.json` | 目标根目录、语言、界面偏好等 | 可读可写；无文件时使用默认值；损坏时不崩溃 |
| `rules-learned.json` | 用户确认与回滚产生的本地规则 | P0 可加载并参与分类；不提供编辑入口 |
| `history.json` | 迁移/回滚记录 | 每次操作必须写入；支持后续分页读取 |
| 操作日志 | 排查与验收取证 | 每次扫描/迁移/回滚可追溯到阶段与结果 |

**验收标准**

##### AC-STORE-01 首次运行初始化

- **输入/前置**：目标根目录不存在或为空；配置文件不存在。
- **用户动作**：首次启动。
- **预期输出**：创建所需的配置目录与默认文件；默认目标根为 `D:\DiskWarden\`；界面可用；不因目录已存在而覆盖用户数据。
- **异常分支**：目标根不可写 → 应用可进入"只读降级模式"（可扫描、不可迁移/回滚），并提示用户重新指定根目录；不得崩溃或静默失败。

##### AC-STORE-02 写入原子性与并发

- **输入/前置**：迁移过程中写入历史/日志；模拟写入中断。
- **用户动作**：执行操作并强制结束应用。
- **预期输出**：配置文件不出现半截 JSON；重启后可正常读取；历史与日志最多丢失最后一条未完成记录，不影响安全判断。
- **异常分支**：检测到损坏文件 → 保留损坏副本并重建默认文件，提示用户；不得清空历史或规则而不告知。

##### AC-STORE-03 规则数据缺失或损坏

- **输入/前置**：规则数据文件缺失、字段缺失或无法解析。
- **用户动作**：启动并扫描。
- **预期输出**：应用不崩溃；未命中规则的条目按"未知黄色"处理；明确提示"规则数据异常，部分条目需人工确认"；不得把未知条目默认视为绿色。
- **异常分支**：规则数据部分损坏 → 可用的规则继续使用，损坏部分按未知处理并记录。

##### AC-STORE-04 目标根目录变更保护

- **输入/前置**：已存在已迁移条目；用户尝试修改目标根目录。
- **用户动作**：在设置中修改目标根。
- **预期输出**：阻断修改，提示"存在已迁移数据，修改根目录会导致原路径失效，请先全部回滚"；不修改任何链接。
- **异常分支**：用户通过外部方式移动数据 → 下次扫描将相关条目标记为"链接失效"，不自动修复。

### 5.2 操作历史写入（P0）

##### AC-HIS-01 历史记录完整性

- **输入/前置**：执行成功迁移、失败迁移、取消、成功回滚、失败回滚各一次。
- **用户动作**：执行操作后查看历史数据（P0 可通过日志/后续 P1 页面读取）。
- **预期输出**：每次操作都有记录，包含：时间、操作类型、工具、条目、源路径、目标路径、数据量、结果（成功/失败/取消/已回滚）、失败阶段与原因；记录只追加，不覆盖历史。
- **异常分支**：历史写入失败 → 不影响迁移/回滚的数据结果，但必须记录到操作日志并提示"历史未保存"。

##### AC-HIS-02 累计释放口径

- **输入/前置**：完成两次迁移，随后回滚其中一次。
- **用户动作**：查看概览"累计已释放"。
- **预期输出**：累计值为"成功迁移且尚未回滚的条目数据量之和"；回滚后相应扣减；不把失败或取消的数据计入。
- **异常分支**：历史记录缺失导致无法计算 → 显示"统计不完整"，不编造数字。

### 5.3 操作日志（P0）

##### AC-LOG-01 可追溯性

- **输入/前置**：一次失败迁移 + 一次中断恢复。
- **用户动作**：查看日志。
- **预期输出**：日志包含时间、任务标识、阶段、条目、源/目标路径、字节数、结果与错误原因；足以还原"失败发生在哪一步、数据在哪一侧"；不记录登录凭证或文件内容。
- **异常分支**：日志写入失败 → 界面提示，但不得阻塞迁移的安全步骤；不得因日志失败而继续执行无法追溯的破坏性操作（应在开始前确保日志可用）。

### 5.4 主界面与状态（P0）

**P0 界面范围**

- 概览卡片：C 盘剩余、目标盘可用、可释放总量、累计已释放。
- Tab：P0 只有"IDE 数据"页接真实数据；项目目录、C 盘全景、规则学习、操作历史可以展示"即将推出"占位，但**不得展示假数据**。
- 详情区：工具信息、条目列表、大小、分类、状态、迁移预览、进度、结果、错误提示。

**验收标准**

##### AC-UI-01 IDE 数据页真实数据

- **输入/前置**：完成一次扫描。
- **用户动作**：查看列表、切换工具、查看条目。
- **预期输出**：工具、条目、大小、分类、状态均来自真实扫描结果；排序正确；已迁移/链接失效有明确标识；概览卡片数字与扫描/历史数据一致。
- **异常分支**：扫描失败 → 展示上次结果并明确标记"数据可能过期"；不得用原型假数据填充。

##### AC-UI-02 状态覆盖完整

- **输入/前置**：依次触发空闲、扫描中、扫描完成、预览、迁移中、失败、回滚完成、空态、进程占用态。
- **用户动作**：走完整流程。
- **预期输出**：每种状态都有明确的界面表现与下一步操作；扫描/迁移期间界面可响应；错误提示包含原因与建议；阻断项在确认前可见。
- **异常分支**：状态切换时旧任务的结果未清理 → 不得把旧进度显示为新任务进度；以任务标识区分。

##### AC-UI-03 迁移确认页信息完整

- **输入/前置**：选择多个条目，包含绿色与已确认黄色。
- **用户动作**：生成预览。
- **预期输出**：展示条目清单、总释放量、总需求量、目标剩余、目标路径、阻断项、警告项；黄色条目显示"已确认"来源；用户可返回修改；确认后进入执行。
- **异常分支**：预览过期（5 分钟）或条目变化 → 要求重新生成预览，不直接执行旧计划。

##### AC-UI-04 进度与结果可理解

- **输入/前置**：执行一次较大数据量迁移。
- **用户动作**：观察进度并等待完成。
- **预期输出**：显示当前阶段（复制/校验/建链/验证）与已处理字节/文件；完成时给出成功/失败摘要与释放量；失败时说明数据现在在哪、是否需要重试；可取消（关键窗口除外）。
- **异常分支**：进度长时间无变化 → 显示"正在处理大文件/等待系统响应"，不伪造进度；任务实际失败时不得停在"进行中"。

##### AC-UI-05 进程占用与阻断提示

- **输入/前置**：工具运行中；目标空间不足；红色条目被尝试选择。
- **用户动作**：尝试迁移。
- **预期输出**：分别提示"请先关闭工具"、"目标盘空间不足，还差 X GB"、"该目录包含登录凭证/配置，不能迁移"；阻断原因具体到条目；不出现只有错误码的提示。
- **异常分支**：多个阻断同时存在 → 全部列出，不只显示第一条。

## 6. 异常与边界场景总表

### 6.1 总表

| 场景 | 触发条件 | 产品行为 | 数据影响 | 对应验收 |
|---|---|---|---|---|
| 进程占用 | 工具进程运行中，或复制期间启动 | 预览阻断；执行中在破坏性步骤前中止；提示关闭工具 | 源不变；临时副本清理 | AC-SCAN-06、AC-MIG-04 |
| 目标盘空间不足 | 可用 < 需求量 | 阻断；显示缺口；执行前复核 | 无写入 | AC-MIG-02、AC-ROL-02 |
| 权限不足 | 读取/写入/删除被拒绝 | 中止并指出路径；不提权；保留数据 | 源不变；残留记录 | AC-MIG-05、AC-ROL-03 |
| 迁移中断 | 崩溃、断电、强制结束 | 重启识别任务；按证据恢复或转人工 | 至少一份完整副本 | AC-MIG-07 |
| 回滚失败 | 复制/校验/权限/清理失败 | 停止自动操作；保留两侧；给出人工步骤 | 不删除任一侧 | AC-ROL-03 |
| 目标盘掉线 | 执行中或回滚前目标不可用 | 阻断/中止；不删链接 | 数据仍在目标盘或源侧 | AC-MIG-03、AC-ROL-05 |
| 目标文件系统不支持 | 网络盘、exFAT/FAT32、只读卷 | 预览阻断 | 无写入 | AC-MIG-03 |
| 链接失效 | 目标被删或盘符变化 | 标记高风险；提供回滚/修复说明 | 不自动修复/删除 | AC-SCAN-09 |
| 配置备份缺失/损坏 | 备份目录缺失或清单不符 | 数据回滚继续；配置标记未恢复 | 现有配置不覆盖 | AC-ROL-06 |
| 重复/并发操作 | 重复迁移、双击、第二个任务 | 拒绝并提示；只允许一个写任务 | 无重复写入 | AC-MIG-11 |
| 长路径 | 任一侧路径超限 | 预览阻断；建议更短目标根 | 无写入 | AC-MIG-12 |
| 扫描权限错误 | 子目录不可读 | 继续扫描；标记不完整 | 只读 | AC-SCAN-03 |
| 配置数据损坏 | JSON 无法解析 | 备份损坏文件并重建；提示 | 不丢历史（除最后一条） | AC-STORE-02/03 |
| 用户取消 | 复制/校验阶段取消 | 停止并清理临时副本 | 源不变 | AC-MIG-09 |
| 退出时有任务 | 有活动写任务 | 拦截退出；强制退出后靠恢复 | 由中断恢复保障 | AC-MIG-07、通用规则 3.4 |
| 规则数据异常 | 文件缺失/部分损坏 | 未知条目按黄色；提示 | 只读 | AC-STORE-03 |

### 6.2 进程占用（必须覆盖）

- **检测时机**：扫描时标记；生成计划时校验；开始复制前校验；进入破坏性步骤前再次校验。
- **阻断范围**：同一工具的所有条目；不因单个条目而误伤其他工具。
- **用户提示**："检测到 `<工具名>` 正在运行，请先完全退出（包括托盘/后台进程）后再迁移。"
- **禁止行为**：不自动结束进程；不把"检测不到"当成"未运行"。
- **恢复**：用户关闭工具后可重新生成计划；已中止任务的临时数据按规则清理，源不动。

### 6.3 目标盘空间不足（必须覆盖）

- **计算口径**：数据字节 × 1.05 + 64 MiB；批量按汇总计算，同时逐条校验。
- **阻断表现**：预览中显示需要/可用/缺口；执行按钮不可用；更换目标后可重新预览。
- **动态变化**：执行前复核；复制过程中若目标盘写满 → 中止，源不变，临时数据按规则清理，提示释放空间或更换目标。
- **回滚同理**：C 盘空间不足时阻断回滚，保持链接与目标数据不动。

### 6.4 权限不足（必须覆盖）

- **常见原因**：文件被其他进程占用、ACL 拒绝、目标目录只读、企业策略限制。
- **产品行为**：中止当前任务；指出具体路径；提示"文件可能被占用或权限不足"；建议关闭相关程序或以有权限的用户身份运行；**不请求管理员权限、不自动修改 ACL**。
- **数据安全**：源数据只读；不留下失效链接；临时副本清理失败时记录位置，不删除源。
- **验收**：AC-MIG-05、AC-ROL-03。

### 6.5 迁移中断（必须覆盖）

- **中断场景**：应用崩溃、断电、任务管理器强制结束、系统重启。
- **恢复原则**：
  1. 以任务记录（先记意图、再执行、后记结果）和实际文件系统观测为依据。
  2. 只做有明确证据的动作；证据不足时标记"恢复待处理"。
  3. 任何情况下保证至少一份完整可读数据。
  4. 恢复结果必须落到明确状态，不允许停留在"进行中"。
- **用户可见**：重启后显示未完成任务、已采取的恢复动作、当前数据位置；可查看诊断信息。
- **验收**：AC-MIG-07（覆盖复制前、复制中、建链前后等阶段）。

### 6.6 回滚失败（必须覆盖）

- **失败定义**：回迁复制失败、校验失败、权限不足、清理链接失败、恢复配置失败等。
- **产品行为**：立即停止自动操作；标记"回滚失败/恢复待处理"；保留源路径链接与目标数据中至少一条可用路径；不删除任何一侧；提供重试与人工步骤。
- **禁止行为**：失败后继续清理目标数据；把失败显示为成功；自动修改链接指向其他位置。
- **验收**：AC-ROL-03、AC-ROL-04、AC-ROL-06。

### 6.7 其他边界

- **路径安全**：目标不得位于源目录内部；不跟随链接；删除只针对任务记录的精确路径。
- **文件变化**：扫描后条目发生变化时，执行前复核；明显变化要求重新扫描，不按旧快照继续。
- **磁盘格式**：目标必须支持 Windows 目录链接；P0 默认仅支持固定本地 NTFS 卷。
- **多用户/多会话**：P0 面向当前登录用户；不处理其他用户的数据根。
- **系统还原/杀软**：被安全软件拦截时按权限不足处理，提示用户放行，不尝试绕过。

## 7. P1 / P2 模块范围

> 本节只定义范围与出口，不展开逐条验收；进入对应阶段前需补充详细验收标准。

### 7.1 M4 规则学习（P1）

**目标**：让产品记住用户的选择，减少重复确认；全部本地，不上传。

**范围**

1. 规则学习页：展示已学习条目、来源（手动/迁移未回滚/回滚）、时间、当前安全等级。
2. 手动标记：用户可把绿色降为红色（不再推荐）、把黄色确认为绿色或红色；**红色不可被解锁为可迁移**。
3. 迁移未回滚自动绿色：同一目成功迁移且观察期内未回滚，自动加入绿色；观察期默认 7 天，待确认 Q3。
4. 回滚自动红色：回滚过的条目加入红色，后续不再推荐。
5. 学习结果在下次生成计划时生效；不修改历史记录。

**出口标准**

- 学习页展示真实数据；手动标记后下一次计划立即生效；红色不可逆；无网络请求；规则文件损坏时按未知黄色处理。

**不做**：云端规则同步、跨设备同步、AI 推断。

### 7.2 M5 项目目录（P1）

**目标**：让用户看到项目里的 `node_modules`、`build`/`dist`、`.git` 占用，按项目排序。

**范围**

1. 列出 IDE 最近打开/用户指定的项目；显示各项目及子目录体积；按大小排序。
2. 提供打开目录、复制路径等只读操作。

**边界**

- "项目迁移 + 自动修复 workspaceStorage 映射"涉及 IDE 内部状态，技术可行性与风险需单独设计评审；在评审通过前不进入 P1 实现（待确认 Q12）。
- 不删除 `node_modules` 或项目文件。

### 7.3 M6 C 盘全景（P1）

**目标**：只读盘点 C 盘大头，帮助用户发现非 IDE 的占用。

**范围**

- 展示 Android SDK、Gradle、Docker、npm/pnpm/yarn、pip、Cargo、Go modules、Ollama 等已知位置的占用（以规则数据为准）。
- 支持按大小排序、打开目录、复制路径。
- 明确标注"仅盘点，不自动清理"。

**边界**

- P1 不做一键删除、不做非 IDE 目录迁移；相关能力若要做，需单独安全评审并列入后续范围。

### 7.4 M7 操作历史（P1）

**目标**：把 P0 已写入的历史变成可浏览、可筛选的页面。

**范围**

- 历史列表：时间、操作类型、工具、条目、数据量、结果。
- 筛选：按类型、工具、结果、时间范围。
- 详情：源/目标路径、失败阶段与原因、恢复动作。
- 统计：累计已释放（当前仍生效）、成功/失败/回滚次数。

**边界**

- 不提供跨设备同步；不提供自动上传诊断。
- P0 必须已写入历史数据；P1 只做展示，不改变写入口径。

### 7.5 M8 自动维护（P2）

**目标**：周期性清理可再生缓存，减少 C 盘回涨。

**范围（若人类确认保留）**

- 默认关闭；用户显式开启并选择周期（默认每周）。
- 只处理规则数据中明确标记为"可再生缓存"的绿色目录；绝不处理红色、黄色或用户文件。
- 清理前展示将删除的条目与预计释放量；清理动作不可回滚，必须二次确认。
- 每次清理写入历史与日志；失败不影响其他条目。

**边界与待确认**

- 决策 0001 未把自动维护列入 P1，本规格按 P2 归档。
- 是否保留该模块、清理对象范围、是否允许自动执行删除，均需人类确认（Q5）；确认前不实现。
- 自动维护不包含迁移，也不得自动修改目录链接。

### 7.6 模块外交付项（仅登记）

- P1：打包、托盘、开机自启、日志查看、完整设置页、欢迎页/OAuth/Star、官网、诊断信息导出。
- P2：云端规则同步、CI、Mac 版、自动更新。
- 这些交付项不改变 8 个模块的优先级，也不进入 P0 验收。

## 9. 验收执行方式与 P0 出口

### 9.1 测试环境

- Windows 10/11 x64 真机或虚拟机。
- 所有迁移/回滚测试在**沙箱目录**中进行，模拟 `%APPDATA%` / `%USERPROFILE%` 结构；**禁止使用真实用户目录做破坏性测试**。
- 中断与断电场景在虚拟机快照中执行，可反复还原。
- 至少覆盖：Cursor、Trae CN（新旧目录）、Claude Code 各一个样本；规则数据覆盖绿色、红色、黄色三类。

### 9.2 用例覆盖

| 类别 | 必须覆盖 |
|---|---|
| 扫描 | 正常识别、新旧目录并存、大小统计、权限错误、链接跳过、已迁移、链接失效、取消、空态 |
| 迁移 | 单条成功、批量、空间不足、目标不可用、进程占用、权限不足、校验失败、建链失败、长路径、取消、重复/并发 |
| 回滚 | 单条成功、批量、空间不足、目标掉线、校验失败、权限不足、配置恢复四种场景、重复回滚 |
| 中断恢复 | 复制前、复制中、复制完成未建链、换位后未建链、建链后未验证；回滚复制中、校验中、清理前 |
| 数据完整性 | 每次成功/失败/中断后，比对相对路径集合、文件数、每文件大小、总字节；任意时刻至少一份完整副本 |
| 安全 | 红色不可选、黄色必须确认、不跟随链接、不请求提权、不联网、删除路径精确 |

### 9.3 P0 通过标准

同时满足以下条件，才视为 P0 完成：

1. 本文档所有 P0 验收项（AC-SCAN、AC-MIG、AC-ROL、AC-STORE、AC-HIS、AC-LOG、AC-UI）通过。
2. 在沙箱中完成一次"扫描 → 迁移 → 验证 → 回滚"闭环，迁移前后数据零丢失。
3. 所有异常场景都能落到明确状态，用户能看到"数据在哪、是否安全、下一步做什么"。
4. 不请求管理员权限；扫描、迁移、回滚过程无网络请求。
5. 操作历史与日志可追溯到每个任务的阶段与结果。
6. 测试报告包含用例编号、执行结果、前后数据清单（相对路径 + 字节 + 文件数）、失败截图/日志。

### 9.4 不作为 P0 验收项的指标

- 界面视觉精细度、动画、品牌表现。
- 扫描与复制的绝对性能；参考目标：SSD 上 20 万文件 / 50 GB 元数据扫描 ≤ 15 秒，取消在 1 秒内生效，迁移期间界面操作延迟 < 100 ms。未达标需记录，但不作为阻断项。
- P1/P2 模块的任何功能。
- 自动启动 IDE 验证（待确认 Q4）。
