## 3. 如何执行

```bash
# 全量（自动选规模：磁盘剩余 ≥9 GiB 时用 real）
python tools/run_e2e.py

# 快速回归
python tools/run_e2e.py --scale=small

# 单个模块 / 保留沙箱便于现场排查
python tools/run_e2e.py --case test_rollback
python tools/run_e2e.py --keep

# CI 现有的 pytest 路径同样会收集本套件（conftest 自动降为 small）
python -m pytest tests -q
```

* 每条用例在临时目录下新建独立 profile（`appdata/Roaming/<IDE>`、`appdata/Local`、DiskWarden 数据根、目标盘），用完即删（`--keep` 可保留）。
* 失败用例的完整 stdout 与逐用例 JSON 事件日志（`sandbox-<pid>.log`：阶段、耗时、job_id、恢复结果、数据校验）都会保留，可直接随 bug 单提交。
* 真实 `%APPDATA%` / `%LOCALAPPDATA%` / `%USERPROFILE%` 从不读写；`test_scan` 显式断言每条扫描结果都落在沙箱内、且不以真实 `%APPDATA%` 为前缀。

### 规模策略

| 规模 | 夹具 | 用途 |
| --- | --- | --- |
| `real`（验收默认） | 2 个 1.2 GiB / 0.9 GiB 大文件 + 260 个 32 KiB 批量文件 + 16 MiB 中文件 + 40 个日志，共 **2,227,306,899 B（2.074 GiB）/ 269 文件 / 目录深度 5** | 验收、性能与硬中断实测 |
| `small` | 6/2 MiB 大文件 + 120 个 16 KiB 文件等，约 **10.4 MiB / 129 文件** | 本地快速循环、CI |

`real` 规模由 `test_scan` 强制断言 ≥ 2 GiB，防止有人把小文件调回去让各阶段"秒过"。

## 6. 崩溃恢复实测结果

> 本节是 T15 用户说明 / Release Notes 的直接输入。

方法：在子进程中执行真实迁移，于四个阶段边界调用 `os._exit(137)`（等价于用户强关窗口 / 断电），随后在同一数据根上启动**全新的 `AppService`**，检查重启识别、恢复/回滚入口、数据完整性与 IDE 可用性。四个阶段各跑一次 real 规模（2.074 GiB / 269 文件）。

| 中断点 | 重启后 job 状态 | recovery 入口 | preview 模式 | 恢复结果 | 杀进程耗时 | 恢复耗时 | 恢复后 source | 恢复后目标 | 数据完整 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **swap**（目标已提升，源未改名） | `COPY_VERIFIED` | recover + rollback | `residual_copy`（`can_proceed=false`） | `FAILED`（`ok=false`），目标副本被删除，源未动 | 1.30 s | 0.13 s | 真实目录，2.07 GiB 全量哈希一致 | 不存在 | ✅ |
| **link**（源已改名为 tombstone） | `COPY_VERIFIED` | recover + rollback | `blocked`（`can_proceed=false`） | `ROLLED_BACK`（`rolled_back=true`），源恢复 | 1.49 s | 0.15 s | 真实目录，哈希一致 | 不存在 | ✅ |
| **link_verify**（junction 已建） | `COPY_VERIFIED` | recover + rollback | `rollback`（`can_proceed=true`） | `DONE`（`ok=true`，"link is valid"） | 1.33 s | 0.40 s | 链接 → 目标 | 真实目录 | ✅（经链接读全量一致） |
| **cleanup**（链接已校验、待删 tombstone） | `COPY_VERIFIED` | recover + rollback | `rollback`（`can_proceed=true`） | `DONE`（`ok=true`） | 1.69 s | 0.39 s | 链接 → 目标 | 真实目录 | ✅ |

四种情况下共同验证到的结论：

1. **重启一定能识别未完成 job**：`recovery_list` 返回 1 条，类型 `migration`，源路径与目标路径正确，同时给出 `recover` 与 `rollback` 两个入口，`needs_human=false`。
2. **journal 在四个窗口内都停在 `COPY_VERIFIED`**：`_migrate_one` 只在 PLANNED / COPY_VERIFIED / 终态写 journal，因此恢复完全依赖现场观测（staging、final、tombstone、junction 的实际形态）而不是 journal 的阶段字段 —— 这是当前设计的正确行为，但也意味着**后续若在 S5–S9 增加 journal 写入，本矩阵必须同步扩充**。
3. **数据零丢失**：四种情况下源目录（或链接）与目标目录的全量哈希、文件数、总字节均与迁移前一致；`appdata/Roaming/Cursor` 其它文件（`settings.json` 等）字节不变。
4. **IDE 仍可用**：`Cursor.exe` 存在且可读，`settings.json` 内容未被改写，缓存目录层级未被打平（深度 5）。
5. **无残留**：不含 `.dw-partial-*` / `.dwtombstone-*` / `.dw-restore-*`；恢复后 `recovery_list` 归零。
6. **耗时可接受**：2 GiB 规模下恢复在 0.13 ～ 0.40 s 完成；用户侧感知为"重启后弹一条待恢复提示，点一下即结束"。

**需要在 T15 用户说明中如实写明的两点：**

* **swap 窗口（副本已就绪、源目录尚未改名）没有可用的"回滚"路径**：preview 返回 `residual_copy` 且 `can_proceed=false`；带确认参数调用会直接抛 `FrozenInstanceError`（DEF-01），而 `requires_residual_confirm` 因 DEF-04 永远为 false。当前唯一的出路是"恢复"——它会删除已提升的副本、把 job 标为失败，用户需要**重新发起一次迁移**。数据不会丢，但用户会看到一次"失败"。
* **link 窗口的 rollback 入口是 `blocked`**：源路径此刻只剩 tombstone，preview 无法通过预检。UI 在这个状态下应把"恢复"设为唯一主按钮，避免用户点"回滚"得到一次无意义的阻断提示。

## 7. 回滚一致性实测

real 规模、迁移完成后再回滚：

* 回滚完成后原路径是**真实目录**（`is_junction` 为假），不是链接；
* 文件数、总字节、逐文件 SHA-256 与迁移前完全一致；
* 目标目录被删除，无 `.dw-partial-*` / `.dwtombstone-*` / `.dw-restore-*` 残留；
* 回滚写入独立的 `TYPE_ROLLBACK` journal（`ROLLED_BACK`），迁移 journal 保留 `DONE` 作为审计轨迹 —— 初版用例曾误判为同一份 journal，已按产品实际契约修正；
* 已回滚条目在下次扫描中降级为红色 `requires_confirm=true`，再次迁移被 `BLOCKED_RED_PATH` 拒绝；
* 对已完成回滚再次 preview 返回 `mode=already_rolled_back` 且 `can_proceed=false`、不下发 plan（幂等，不产生副作用）。

## 8. 沙箱隔离验证

* 所有输入路径由 `Sandbox` 在临时目录下生成，`test_scan` 对每条扫描结果断言"必须落在沙箱内"，并额外断言"不得以真实 `%APPDATA%` 为前缀"。
* 磁盘占用、目标盘、数据根、日志目录全部指向沙箱；测试结束自动清理（`--keep` 显式保留）。
* 子进程中断测试同样只操作沙箱，`kill_child.py` 通过环境变量接收沙箱路径，不含任何真实路径硬编码。
* 运行日志集中在 `tests/e2e/logs/`，已用该目录下的 `.gitignore` 排除，不入库（不改动共享仓库的 `info/exclude`）。

## 9. 已知缺陷

| 编号 | 严重度 | 位置 | 现象 | 影响 | 钉住的用例 |
| --- | --- | --- | --- | --- | --- |
| DEF-01 | **P1 阻断** | `src/app/service.py:1571`（`RollbackRequest` 为 `@dataclass(frozen=True)`，见 `src/core/rollback/models.py:115`） | `rollback_preview(job_id, confirm_residual_delete=True)` 抛 `FrozenInstanceError: cannot assign to field 'confirm_residual_delete'` | swap 窗口崩溃后，用户**无法确认删除残留副本**，回滚入口在 bridge 层完全不可用（只能走 recover） | `test_confirmed_preview_is_reachable` |
| DEF-02 | P2 | `src/core/store/journal.py:114` | 非法格式 job_id 触发 `StoreError: invalid journal job id`，直接穿透 bridge 封装 | 前端只识别 `BridgeError`，收到未包装异常后表现为未知错误，文案与错误码不可控 | `test_malformed_job_id_is_rejected_as_a_bridge_error` |
| DEF-03 | P2 | `src/core/rollback/engine.py:694 / 717-724` | 残余副本删除成功后 `result.state` 仍是 `RESIDUAL_COPY`，`ok=false`，成功文案被塞进 `error_message`，journal 也写 `RESIDUAL_COPY` | 清理成功却显示失败；`recovery_list` 仍持续列出该 job | `test_residual_cleanup_reports_a_terminal_state` |
| DEF-04 | P2 | `src/app/service.py:1580 / 1594` | 用小写 `mode`（`residual_copy`）与大写 `state`（`RESIDUAL_COPY`）比较，恒为 false | `requires_residual_confirm` 永远 false，UI 永远不会提示"需要确认删除副本"；与 DEF-01 叠加使残余清理在 UI 侧彻底不可达 | `test_residual_preview_asks_for_confirmation` |
| DEF-05 | P3 一致性 | `src/app/service.py:1374` | `_migrate_one` 调 `complete_migration` 时未传 `process_provider`（也未传 `ops`） | S5–S9 永远用默认 psutil 探测，忽略调用方传入的 provider；生产行为目前正确（真实进程枚举），但测试/未来虚拟化只能 monkeypatch（`tests/e2e/support.py:282-318`） | 由 `test_starting_the_ide_after_planning_stops_the_swap` 的 hook 绕过，建议一并修正 |

**DEF-01 与 DEF-04 是同一处代码的两个错误**，建议一起修：把 `frozen=False` 或改用 `dataclasses.replace`，并统一 mode/state 命名空间（或在比较处改用 `MODE_RESIDUAL_COPY`）。修复后 4 个 xfail 会自动变为 unexpected success，去掉装饰器即可作为回归保护。

**复现步骤（DEF-01，最短路径）**

1. 沙箱内迁移一个 IDE 缓存目录，在 S5 提升目标后、S6 改名源目录前杀死进程（`test_hardkill` 的 `swap` 阶段）。
2. 重启后 `recovery_list()` → 取 `job_id`。
3. 调 `rollback_preview(job_id, confirm_residual_delete=True)`。
4. 预期：`can_proceed=true` 并返回 plan；实际：`FrozenInstanceError`。

## 10. 风险与建议

| 风险 | 等级 | 说明 / 建议 |
| --- | --- | --- |
| 残余副本清理在 UI 不可达（DEF-01 + DEF-04） | 高 | 发布前修复；在此之前 T15 说明不要承诺"任何崩溃都能回滚" |
| swap 窗口恢复结果是 `FAILED` 而非 `ROLLED_BACK` | 中 | 产品语义上可接受（数据未动、重试即可），但用户说明需解释"这是预期的收尾，不是数据事故" |
| link 窗口 rollback 预览为 `blocked` | 中 | UI 在该状态把"恢复"设为主操作、隐藏或禁用"回滚" |
| journal 只在三处写入，恢复依赖现场观测 | 中 | 后续若在 S5–S9 增加 journal 写入，必须同步扩充硬中断矩阵，否则恢复分支覆盖失效 |
| `os._exit` 模拟断电，不等价于物理掉电 | 中 | 已覆盖进程级崩溃与操作系统缓存正常刷盘的场景；真实掉电导致的 NTFS 元数据半写不在本期范围，建议后续加磁盘级故障注入 |
| 仅验证 Windows/NTFS（junction 语义） | 中 | 一期产品 Windows 优先；macOS/Linux 需另建矩阵（符号链接与权限模型不同） |
| 合成数据不含超长路径 / 复杂 ACL | 低 | 权限不足用 `deny_scandir` 注入覆盖；超长路径（>260）建议单列用例 |
| CI 现在会跑 e2e（small） | 低 | `tests/e2e/conftest.py` 已固定 small + 临时根目录，避免 CI 触发 2 GiB 夹具；若需要更快，可在 CI 设置 `DISKWARDEN_E2E_SCALE=small` 或按 marker 排除 |
