本任务实现扫描链路的第一层：按 `data/ide-catalog.json` 枚举已知 IDE/CLI，判断每个目录条目在本机是 **已存在 / 不存在 / 无权限**。不统计大小、不检测进程、不做红黄绿规则判定（分别属于 T08、T08、T07）。

- 覆盖目录 `src/core/scan/`，纯标准库实现，Python 3.8 可运行，未新增任何依赖。
- 30 个工具、162 个目录条目全部参与扫描；不存在的路径跳过并记录状态，不会中断整轮扫描。
- 环境变量大小写不敏感，路径中不含硬编码用户名或盘符。
- 全程只读：只调用 `os.stat` / `os.scandir`，不创建、不修改、不删除任何被扫描内容。
- 单元测试 16 个，全部通过；本机实测扫描 30 个工具，输出三种状态。

## 3. 关键设计

### 3.1 状态语义

| 状态值 | 中文 | 判定 |
|---|---|---|
| `present` | 已存在 | 至少解析出一条实际存在的路径（目录/文件/glob 匹配） |
| `absent` | 不存在 | 路径不存在、类型不符、或环境变量无法解析 |
| `no_permission` | 无权限 | 枚举父目录或 `stat` 目标时被拒绝（`PermissionError` 或其他 `OSError`） |

工具级状态按目录条目汇总：

1. 任一条目 `present` → 工具 `present`；
2. 否则任一条目 `no_permission` → 工具 `no_permission`；
3. 否则 `absent`。

所有 catalog 工具都会出现在结果中，包括全部路径都不存在的工具，界面可直接展示“未安装”。

### 3.2 路径解析流程

1. **环境变量展开**：把 catalog 模板中的 `%APPDATA%` / `%USERPROFILE%` / `%LOCALAPPDATA%` 替换为注入的环境映射；键名统一大写比较，因此 `%appdata%` 与 `%APPDATA%` 等价。未知变量不会抛到上层，而是标记该条目 `absent` 并产生 `unresolved_environment` 警告。
2. **按段解析**（`ntpath`，以反斜杠分割）：
   - 普通段：直接拼接；
   - `<...>` 占位段（如 Claude Code 的 `<项目>`、`<session>`、JetBrains 的 `<产品><版本>`）：只枚举父目录的**直接子项**，中间层只保留目录；不做递归；
   - 含 `*` / `?` 的段（catalog 只允许出现在 glob 条目的最后一段）：枚举父目录直接子项后按段名做 `fnmatch`。
3. **最终类型校验**：`dir` 必须是目录、`file` 必须是文件、`glob` 接受匹配项；类型不符记为 `absent`，明细为 `type_mismatch`。
4. **去重**：多个占位符组合可能解析到同一路径，按 `os.path.normcase` 大小写不敏感去重，输出排序稳定。
5. **截断保护**：任何单条路径失败只影响该条目，不会中断其余工具/目录的扫描。

### 3.3 异常处理矩阵

| 情况 | 结果 | 警告 |
|---|---|---|
| 父目录或目标不存在 / 不是目录 | `absent` | 无（属于正常“未安装”状态） |
| 环境变量缺失 | `absent`，`detail=unresolved_environment` | `unresolved_environment` |
| 目录无权限 / `stat` 被拒绝 | `no_permission` | `permission_denied`（附系统错误信息） |
| 其他 `OSError`（如超长路径、非法名称） | `no_permission`（无法确认存在性） | `permission_denied`，消息带原始错误 |
| 路径存在但类型不符 | `absent`，`detail=type_mismatch` | 无 |

### 3.4 只读保证

`discovery.py` 只依赖 `os.stat` 与 `os.scandir`，不包含任何写入、创建、重命名、删除调用。测试 `test_scan_does_not_modify_the_scanned_tree` 在扫描前后对整棵临时目录树做快照（相对路径、大小、`mtime_ns`、是否目录）并逐项比较，证明扫描无副作用。

### 3.5 与规则层的关系

扫描层只报告事实，不导入规则引擎，也不读取 `data/rules.json`。`PathHit` 原样携带 catalog 的 `safety`、`reason`、`handling`，供 T07 在分类时直接使用，避免二次查表。

## 4. 数据模型摘要

```text
PathHit
  template       catalog 原始模板（如 %APPDATA%\Cursor\Cache\）
  pattern        环境变量展开后的路径（glob 保留 *）
  type           dir | file | glob
  safety         green | yellow | red（来自 catalog，不在本层判定）
  reason         来自 catalog
  handling       可选，来自 catalog
  status         present | absent | no_permission
  resolved       实际解析到的具体路径列表
  detail         not_found | type_mismatch | permission_denied | unresolved_environment

ToolDiscovery
  id / name / kind
  status         工具级三态
  counts         total / present / absent / no_permission
  directories    每个 catalog 条目的 PathHit

ScanDiscovery
  tools          全部工具（含未安装）
  warnings       环境变量缺失、权限不足等
  summary()      工具与目录的数量汇总
```

## 5. 用法

在仓库根目录执行（只读）：

```bash
# 汇总视图
python -m src.core.scan

# 完整 JSON（供 UI/宿主桥联调）
python -m src.core.scan --json

# 只看某个工具，并列出每个路径
python -m src.core.scan --tool cursor --verbose

# 指定其他 catalog
python -m src.core.scan --catalog data/ide-catalog.json
```

```text

directories: 162 total, 99 present, 63 absent, 0 no_permission
warnings: 0
```

本机只保留了旧 `Trae CN` 根目录，扫描同时报告 `TRAE SOLO CN` 条目的状态，工具级仍为 `present`；这与 catalog 中“新旧根目录并存”的维护约定一致。

## 8. 风险与限制

1. **占位符段会枚举全部直接子项**：如 JetBrains 的 `<产品><版本>` 会匹配父目录下所有子目录。当前只在存在性判断中使用，可接受；若 T07 需要精确产品名，应由 catalog 增加显式条目或特征规则。
2. **只判断“路径是否存在”**：卸载后残留的空目录仍会让工具显示 `present`。这是第一层识别的固有语义，后续可结合可执行文件/进程证据增强。
3. **长路径（>260 字符）**：未做 `\\?\` 规范化；失败会归为 `no_permission` 并带原始错误。长路径统一处理属于平台适配层，T08 起跟进。
4. **无权限状态未在真机自然复现**：本机扫描为 0 个 `no_permission`，该状态由 `stat`/`scandir` 的 mock 测试覆盖；后续应在受限账户或受保护目录上做一次实测。
5. **catalog 数据未逐项实机验证（风险 R8）**：本层只忠实执行 catalog；条目本身的准确性由 T03 维护与后续全量实测保证。
6. **大小写不敏感依赖 Windows 语义**：`os.path.normcase` 在 POSIX 上不去重；P0 仅 Windows，Mac/Linux 适配时需重新确认。
