## 1. 字体与字号

**F-01（P0，已改）中文优先字体栈让西文和数字全部走 YaHei**
- 现状：`body{font-family:"Microsoft YaHei UI",...,-apple-system,"Segoe UI",sans-serif}`——Windows 上英文、数字全部由 YaHei 渲染，字宽和基线都不对，这是「中文网页」最直观的信号；`-apple-system` 排在 `Segoe UI` 之前，在 Windows 上永远取不到。
- 改法：收进 Token `--font-ui:"Segoe UI Variable Text","Segoe UI","Microsoft YaHei UI",…`，西文/数字先走系统 UI 字体，中文回退 YaHei UI；等宽栈统一为 `--font-mono:"Cascadia Mono","Segoe UI Mono",Consolas,…`；`-webkit-font-smoothing:auto`（不用网页的 antialiased 细体）。
- 影响页面：全部（顶栏、五个 Tab、四个弹窗、欢迎/点星）。

**F-02（P0，已改）字号阶梯是网页博客的尺度**
- 现状：页面标题 19px、KPI 26px、小标题 16px、正文行高 1.55，外加 9 处 `letter-spacing:.2~1px`（桌面原生控件不做字距调整）。
- 改法：阶梯压到 `--fs-page:16 / --fs-title:15 / --fs-sub:14 / --fs-kpi:22`，正文行高 1.4，`letter-spacing` 全部删除（残留 1 处在注释里）。
- 影响页面：全部。

**F-03（P1，已改）正文字重用了非法值**
- 现状：`.tcell.tpath{font-weight:550}`，浏览器会自行取整，同一份 CSS 在不同渲染下不一致。
- 改法：统一为 500/600 两档；数字列一律 `font-variant-numeric:tabular-nums`。
- 影响页面：IDE 数据目录明细、C 盘全景、操作历史、迁移预览表。

## 2. 视觉层级

**F-04（P0，已改）顶栏是渐变横幅，不是工具栏**
- 现状：`.topnav{height:96px;background:linear-gradient(180deg,#4dca52,#41c046,#39b23f);box-shadow:inset 0 1px 0 rgba(255,255,255,.28),0 1px 4px …}`——96px 高的渐变绿条 + 内高光，是网页 hero banner 的做法；白字压在 #41c046 上对比度只有 2.4:1，读不动。
- 改法：48px 单值平面 `--brand-bar:#1e7d27` + 1px 下描边 `--brand-bar-line`，去掉全部渐变与阴影；白字对比度 5.2:1，过 WCAG AA。
- 影响页面：全部（顶栏常驻）。

**F-05（P0，已改）标题装饰条 + 阴影堆叠**
- 现状：`.panel-head h2`、`.bar-title`、`.section-title h3`、`.modal-head h3` 四类标题前挂 3px 绿色 `::before` 竖条（典型网页小标题），卡片同时用圆角 8px + 阴影 + 渐变底。
- 改法：删掉 4 处装饰竖条和 1 处死规则；层级改由描边（`--line` / `--line-strong`）和留白承担；圆角收到 `--radius:4px / --radius-sm:2px / --radius-lg:6px`；阴影只剩两处真正浮起来的元素（弹窗 `--shadow`、toast `--shadow-sm`），其余全部换成 1px 描边。
- 影响页面：五个 Tab 的面板头、所有弹窗标题。

**F-06（P1，已改）欢迎页用两团径向渐变当背景**
- 现状：`.welcome-mask` 用 `radial-gradient` 铺底，卡片半透明，是落地页写法。
- 改法：遮罩改单色 `var(--bg)`，卡片改实色白 + 1px 描边。
- 影响页面：欢迎/登录弹窗。

## 3. 信息密度

**F-07（P0，已改）列表行高按「呼吸感」放大 40%**
- 现状：`.trow{min-height:48px}`，`.content` 间距 12px，`.detail` 内边距 16/18px，空态 `padding:60px`。一屏只能看到 6~7 条目录，而这是要逐条勾选的文件工具。
- 改法：行高收进 Token `--row-h:34px`，内容区间距 8px，详情区内边距 12/14px，空态 28px。行高从 48px 到 34px，同一块固定高度区域可多容纳约 40% 的行。
- 影响页面：软件列表、目录明细、规则表、历史列表、C 盘分类。

## 4. 控件质感

**F-08（P0，已改）按钮缺 active 态，禁用靠整块半透明**
- 现状：`.btn` 只有 hover；禁用统一 `opacity:.55`（连带把背景洗成灰白，文字对比度不足）；高度不固定，中文 26px、英文换行就变 40px。
- 改法：`.btn{padding:5px 12px;min-height:26px;font-size:13px}` 固定几何；primary/ghost/danger/soft/ai 五类各补 `:active`（1px 内凹 + 深色描边，模拟系统按钮按下）；禁用改为显式三件套 `--disabled-bg / --disabled-ink / --disabled-line`，不再用透明度。
- 影响页面：所有工具栏、表格行内按钮、弹窗底部动作区。

**F-09（P1，已改）系统状态芯片是网页 pill**
- 现状：`.system-chip{height:30px;border-radius:15px;background:rgba(255,255,255,.16)}`——半透明大圆角胶囊贴在渐变条上。
- 改法：26px 高、2px 圆角、透明底 + 1px 描边，与顶栏同色系；`.nav-count` 从图标右上角挪到标签之后（原来绝对定位在角上，改成行内导航后必然压字）。
- 影响页面：顶栏右侧账号/版本区。

**F-10（P1，已改）开关、输入框、复选框无统一焦点语言**
- 现状：`:focus-visible` 用浅绿 `#7fd383`（在白色卡片上约 1.6:1，看不见）；输入框焦点靠外发光阴影。
- 改法：焦点色统一为 `--focus:#1560c9`（系统蓝），2px 轮廓 + 1px offset；输入框/下拉/文本域焦点改为 `inset 0 0 0 1px` 内描边（系统控件的写法，不占布局）。
- 影响页面：搜索框、设置弹窗表单、反馈弹窗、AI 弹窗。

## 5. 表格

**F-11（P0，已改）规则学习表超出高度被裁掉，滚不动也看不到表头**
- 现状：`.learned-table` 直接挂在 `overflow:hidden` 的 `.panel-body` 上——行数一多，尾部行被硬裁，且表头不跟随。这是本次走查里唯一一条**功能性不可用**。
- 改法：外层包 `.table-wrap.scroll-y`，`flex:1;min-height:0;overflow:auto`；表头 sticky 规则从 `.scroll-y > .table`（子选择器，包一层就失效）放宽为 `.scroll-y .table`，并补 `inset 0 -1px 0` 分隔线。
- 影响页面：规则学习。

**F-12（P0，已改）长路径列中途断字**
- 现状：路径列 `overflow-wrap:anywhere`，1280px 下 `C:\Users\dev\AppData\Roaming\Cursor\User\workspaceStorage` 会断成 `…\Co\nde\Cache`，Windows 路径被腰斩，读起来像乱码。
- 改法：`pathCell()` 转义后只在反斜杠后插 `<wbr>`，`overflow-wrap:break-word` 兜底——断行只发生在分隔符处；`<wbr>` 不产生文本节点，`copyValue()` 复制到的仍是原路径。列表类窄列改用 `.trunc`（nowrap + ellipsis）并保留 `title` tooltip。
- 影响页面：迁移/回滚预览表、目录明细、规则表、历史详情。

**F-13（P1，已改）无斑马纹、列宽靠内容自适应**
- 现状：表格只有 hover 底色，长短不一的行让列宽每次渲染都在跳；`.learned-table` 无列宽策略。
- 改法：`tbody tr:nth-child(even) td{background:#fcfdfe}`；`.learned-table{table-layout:fixed}` + 34/13/11/19/12/12% 固定列宽（`text-overflow:ellipsis` 在 auto 布局下不生效，必须先固定布局）。
- 影响页面：规则学习、IDE 目录明细、C 盘全景、操作历史。

## 6. 滚动条

**F-14（P1，已改）8px 圆角胶囊滚动条**

## 8. 弹窗 / 遮罩

**F-16（P0，已改）弹窗把内部枚举名当成无障碍名称**

**F-17（P1，已改）遮罩与弹窗阴影层级混乱**

## 验证方法

无法直接跑 pywebview 截图，因此在工作区（**仓库外**）搭了一套只读渲染管线，不写入 `ui/`：

- `harness/server.js` — 本地静态服务，把 `harness/mock-bridge.js` + `harness/fixtures/fixtures.js` 注入到 `index.html` 的**内存副本**；`BASE_UI` 环境变量决定用基线文件还是仓库当前文件。
- `harness/mock-bridge.js` — 假 `window.pywebview.api.rpc`，按 `?view / ?hash / ?overlay / ?lang / ?ide / ?flow` 预置路由与数据。`?flow=migrate` 会真的勾选行并调用 `App.startPreview()`，所以迁移预览截图是走真实渲染路径，不是拼 DOM。
- `harness/run-compare.sh before|after` — 无头 Edge 批量出图：5 个 Tab × {980×720, 1280×800, 1600×900}，加英文态 2 档、4 个弹窗/状态页、2 个遮罩层。
- 回归：`python -m pytest tests -q` → 831 passed；抽出内联 `<script>` 后 `node --check` → 通过。
