## 2. 改动清单

### 2.1 R-01：改用 `DeviceIoControl` 直接写重解析点

`src/platform/win/link.py`

- 删除 `subprocess` 与 `cmd /c mklink` 调用，改为纯 `ctypes`：
  - `_mount_point_buffer()`（第 147 行）按 `REPARSE_DATA_BUFFER` 布局构造挂载点数据
    （`IO_REPARSE_TAG_MOUNT_POINT` + 四个 USHORT 偏移 + 两条 UTF-16LE 名称，长度不含 NUL 终止符）；
  - `_set_reparse_point()`（第 189 行）先 `os.mkdir` 建空目录，再以
    `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS` 打开该目录，
    `DeviceIoControl(FSCTL_SET_REPARSE_POINT)` 写入；失败时带错误码抛 `LinkError`；
  - `_discard_failed_link()`（第 245 行）用 `os.rmdir` 摘除半成品链接（不进入目标）。
- `create_junction()`（第 258 行）在建链后**回读校验**：`read_junction_target()` 经
  `link_target_matches()` 规范化（8.3 短名、大小写）比较；不一致则删链并抛
  `LinkError`，绝不返回一个指向别处的链接。
- 既有语义保持：目标不存在 / 链接路径已存在 / 父目录不存在 → `LinkError`；
  异常文本不含未转义的命令行拼接内容（路径以 `%s` 原样给出，不经 shell）。

因为目标字符串以 UTF-16 缓冲区直达内核，`&`、`|`、`^`、`%`、空格、中文都不再有任何特殊含义。

### 2.2 R-02：校验改为内容指纹

`src/core/migrate/verify.py`

- 新增常量（第 47-51 行）：`FULL_HASH_LIMIT = 4 MiB`、`SAMPLE_BLOCK_BYTES = 64 KiB`、
  `SAMPLE_BLOCK_COUNT = 8`。
- `content_fingerprint()`（第 121 行）：≤4 MiB 整文件 SHA-256（前缀 `sha256:`）；
  更大的文件用 `_sampled_digest()`（第 97 行），对首块、尾块与 8 个均匀间隔块做 SHA-256
  （前缀 `sha256-sampled:`）。偏移量与 `(size, block)` 一并进入摘要，防止「块互换」碰撞。
- `_snapshot()`（第 133 行）由 `(relpath, size)` 升级为 `(relpath, size, fingerprint)`；
  读取失败记入 `errors` 且指纹留空，**不会被当作「内容一致」**。
- `verify_trees()`（第 210 行）逐文件比较路径集合 + 字节数 + 指纹：
  尺寸不同 → `SizeMismatch`；指纹缺失或不同 → 新增的 `ContentMismatch`（带 `rel_path`），
  失败原因形如 `1 file(s) differ in content`。

`src/core/migrate/models.py` / `__init__.py`：新增 `ContentMismatch` 及
`VerifyResult.content_mismatches` / `content_mismatch_count`（含序列化与导出）。

### 2.3 回滚删除前复核（R-02 要求 3）

`src/core/rollback/engine.py`

- 新增 `_content_check()`（第 500 行）：返回 `None` **仅当**两侧可证明逐字节相同；
  校验被取消、读失败（`OSError`）或校验不通过都返回原因字符串 —— 即「校验不可用」按未通过处理。
- 残留副本分支（第 750 行）：确认删除前先比对 `final_path` 与 `source_path`（忽略目标侧独有的
  归属标记 `.dw-owner-<job8>.json`），不通过则 `ERROR_VERIFY` 并拒绝删除。
- 正常回滚的清理步骤（第 1101 行）：删除目标副本前同样复核一次（快照之后、`remove_owned_tree`
  之前），不通过则置 `residual_copy = True`、`ERROR_VERIFY`，报
  `refusing to delete the target copy: ...`，两侧数据都保留。
- 恢复副本的权威校验（第 3 步 `verify_trees(final_path, restore_child)`）自动继承了内容校验。

### 3.1 R-01：目标名含 `&`

构造：目标目录 `targets/a&ver&rem`，同时存在截断前缀 `targets/a`（让旧实现「成功」建出错误链接），
链接名取无特殊字符的 `plain-link`，以便观察链接本身是否建在正确目标上。

| 观察项 | 修复前（`9118bf4`） | 修复后 |
| --- | --- | --- |
| `create_junction` 返回 | 无异常（**静默成功**） | 无异常 |
| 链接是否存在 | True | True |
| `read_junction_target` | `...\targets\a` | `...\targets\a&ver&rem` |
| 回读是否等于请求路径 | **False** | True |
| 经链接能否读到目标数据 | **False** | True |
| `remove_junction` | 抛 `LinkError`：points to `...\targets\a`, expected `...\targets\a&ver&rem` | 正常摘除，目标目录保留 |

修复前 `cmd` 把 `&ver&rem` 当作命令分隔符截断，链接指向真实存在但错误的 `targets\a`，
上层只看到「建链成功」——正是 T14 记录的静默错链。修复后同一场景回读一致、数据可达。
（附带效果：链接名里含 `&` 时旧实现同样会截断到不存在的路径而报错，现已无此问题。）

## 5. 设计取舍与成本

- **4 MiB 阈值**：小文件整文件哈希，代价与文件数线性相关；大文件固定读
  `(8+2) × 64 KiB ≈ 640 KiB`，与文件大小无关，迁移大目录时额外 I/O 有上界。
- **采样而非全量**：无法证明未采样区域完全一致，但能覆盖现实故障模式——截断、
  尾部补零、部分重写、文件互换、块乱序（偏移量进入摘要）。这是「成本可预测」与
  「证据强度」之间的折中，注释中已明确写出。
- **两侧一致采样**：偏移由 `size` 决定，同一比较的两侧必然探测同一批偏移。
- **删除前二次复核**：不复用首次校验结果，而是对「当前实际存在的两侧字节」再验一次，
  因为快照与删除之间存在时间窗（恢复配置、并发写入）。
- `_content_check` 把「读失败/取消」当作不通过，遵循架构 6.1/6.6「宁可失败，不可误删」、
  「源数据在校验通过前只读」。

## 6. 剩余风险

1. **大文件采样盲区**：>4 MiB 文件未采样区段被等长改写仍可能漏检。若要完全消除，
   需要整文件哈希或迁移时记录内容哈希基线（见下条），均超出本任务范围。
2. **无持久化哈希基线**：日志/清单里没有迁移时写下的内容哈希，删除前复核是
   「恢复出的源」对「现存目标」的实时比对，而非对迁移时刻的基线。
   两者同时被同样改写时才可能漏检（需要外部同时篡改两侧）。
3. **额外 I/O**：回滚路径上恢复副本校验 + 删除前复核各一次；大文件每次多约 640 KiB 读。
   实测回滚单测总耗时仍在 0.5 s 量级，未观察到可感知影响。
4. **符号链接/重解析点**：与 `robocopy /XJ` 一致只记录不进入；此类路径的内容不会被比对，
   回滚时也不会被复制（既有行为，未在本任务改变）。
5. 属主标记文件（`.dw-owner-<job8>.json`）在删除前复核中被忽略，否则目标侧天然多一个文件；
   该标记由回滚自身创建，见 `_strip_marker`。
