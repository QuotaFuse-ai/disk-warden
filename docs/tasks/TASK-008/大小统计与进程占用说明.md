## 1. 范围与结论

本任务实现扫描链路的第三层：

1. 对 T06 发现的存在目录/文件递归统计**逻辑字节数与文件数**，输出可被 T09 计划阶段消费的 `ScanItem`；
2. 按 `data/ide-catalog.json` 的 `processes` 字段识别 IDE/CLI 是否在运行，输出 `blocked_by_process`，供迁移前检查直接阻断。

结论：

- 覆盖 `src/core/scan/size.py`、`src/core/scan/process.py`、`src/core/scan/cancel.py` 与平台适配层 `src/platform/`；纯标准库 + 可选 `psutil`，Python 3.8 可运行。
- 迭代式遍历、不跟随任何 junction/符号链接；本机实测发现并跳过了 4 个真实 junction（`.claude\debug\latest`、`.Qoder\logs\latest` 等），不会重复计量或死循环。
- 进度回调默认节流 4 次/秒，取消在目录边界生效，抛出 `ScanCancelled` 并丢弃部分结果。
- 单个目录/条目失败只累加 `access_errors` 并记录 warning，整轮扫描继续。
- 进程名全部来自 catalog，代码中没有硬编码产品名；**进程枚举失败按“状态未知”处理并阻断迁移**，符合产品规格 §5.1。
- 新增 32 个单元测试，全套 87 个测试全部通过。
- 本机全量实测：30 个工具、101 个存在条目、246,393 个文件、9.9 GB，发现+统计+进程检测共 12.7 s，满足“20 万文件 ≤15 s”的目标。

## 3. 公开 API

```python
# 大小统计
measure(targets, cancel_token=None, progress_cb=None,
        throttle_seconds=0.25) -> MeasureReport
targets_from_discovery(discovery) -> list[MeasureTarget]
make_item_id(tool_id, rel_path) -> str          # sha256(tool_id + "\n" + 规范化 rel_path)[:16]

# 进程占用
detect_processes(tools, process_provider=None) -> dict[tool_id, ProcessHit]

# 取消

```

`MeasureReport` 内含 `items`、`warnings`，并提供 `summary()` / `to_dict()`；同时实现了 `__iter__`/`__len__`/`__getitem__`，可以直接当作列表消费。

`ScanItem` 字段与架构 §4.1 一致：`item_id`、`tool_id`、`source_path`、`rel_path`、`kind`、`bytes`、`file_count`、`is_reparse`、`access_errors`、`mtime_max`（UTC ISO8601）。

## 4. 关键设计

### 4.1 迭代遍历与统计口径

- 使用 `os.scandir` + 显式栈，不使用递归，深层目录不会触发 Python 递归上限。
- 只累加普通文件的 `st_size`（逻辑大小，与资源管理器“大小”列同口径）；目录自身元数据不计入。
- `mtime_max` 取目标自身与所有子条目的最大 mtime，供 T09 判断“扫描后是否又被写入”。
- 目录/文件在扫描过程中消失、权限不足、其他 `OSError` 都计入 `access_errors` 并生成 warning（`missing` / `permission_denied` / `measure_failed`），继续处理兄弟条目。

### 4.2 junction / 符号链接

- 链接判定在平台层完成：Windows 检查 `st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT`，POSIX 检查 `S_ISLNK`。
- **不能只用 `DirEntry.is_symlink()`**：Windows 上 junction 的该返回值为 `False`，若据此判断会把链接当普通目录继续遍历，导致重复计量甚至死循环。实现中统一使用 `st_file_attributes`。
- 链接本身不进入统计：不累加字节、不进入目标目录，记录 `reparse_skipped` warning；若目标本身就是链接，`ScanItem.is_reparse = True`、字节数为 0。
- 测试覆盖：嵌套 junction、自指向 junction（`root\loop -> root`）、目标本身是 junction、文件符号链接。

### 4.3 进度与取消

- `progress_cb` 接收字典：`targets_total/targets_done/tool_id/path/bytes_done/files_done/elapsed_seconds/done`。
- 默认 0.25 s 节流（≤4 次/秒）；每个目标的完成事件和最终事件强制发送，`done=True`。
- 取消检查发生在每个目标开始、每个目录出栈、每个条目迭代处；任何位置发现取消都抛出 `ScanCancelled`，不会返回半成品报告。
- `cancel_token` 兼容 `threading.Event` 与自带的 `CancelToken`。

### 4.4 `rel_path` 与 `item_id`

- `rel_path` 相对“工具根目录”（catalog 路径中第一个静态目录段），而不是相对 `%APPDATA%` 展开后的完整路径。例如 `%APPDATA%\Cursor\Cache\` → `Cache`，`%APPDATA%\Cursor\User\workspaceStorage\*.pack` → `User/workspaceStorage/<file>`。
- 计算方式是按模板中工具根之后的段数截取解析结果末尾，因此不受 `%APPDATA%` 展开成多段路径的影响。
- Windows 上 `item_id` 使用小写化的相对路径，跨扫描稳定；`targets_from_discovery` 还会按 `os.path.normcase` 对同一路径去重。

### 4.5 进程占用语义

| status | 含义 | `blocked_by_process` |
|---|---|---|
| `running` | 至少一个进程匹配 catalog 名称 | true |
| `not_running` | 枚举成功且无匹配 | false |
| `no_process_names` | catalog 未给该工具定义进程名（多为 CLI/工具） | false |
| `unknown` | 进程枚举失败（psutil/tasklist/ps 报错） | **true** |

- 匹配大小写不敏感，并忽略 `.exe` 后缀，因此同一份 catalog 可用于 Windows（`Cursor.exe`）与 macOS/Linux（`Cursor`）。进程名缺失时退回可执行文件路径匹配。
- 枚举失败不抛异常、不打断扫描，而是把所有工具标记为 `unknown` 并携带 `error`；计划阶段据此输出 `BLOCKED_PROCESS` 一类阻断，绝不按“未运行”放行。
- `blocked_tool_ids(hits)` 直接返回需要阻断的工具 id 列表，T09 计划层可直接使用。

### 4.6 进程名来源

`detect_processes` 只读取传入 `CatalogTool.processes`；模块内没有任何产品名常量。测试用真实 catalog 断言：注入 `idea64.exe` 时只有 `jetbrains` 变为 running，空 `processes` 的工具永远返回 `no_process_names`。

### 4.7 平台边界

- 业务层不直接调用 `subprocess`/`ctypes`：扫描层只依赖 `src.platform.enumerate_processes` 与 `is_reparse_stat`。
- Windows 优先 psutil，缺失时回退系统自带的 `tasklist`；macOS/Linux 分别回退 `ps`。回退路径不提供 `exe`，仅按进程名匹配。
- 进程枚举结果只包含 `pid/name/exe` 三个字段，不读取命令行、环境变量或用户数据。

## 7. 风险与限制

1. **硬链接**会按目录项重复计入（与资源管理器一致）；如需去重需按 `(st_dev, st_ino)` 记录，本期未做。
2. **稀疏/压缩文件**按逻辑大小统计，与资源管理器一致，但与磁盘实际占用可能不同。
3. **重叠条目**：catalog 同时收录父目录与子目录（如 `projects\<项目>\` 与 `projects\<项目>\memory\`）时，各 `ScanItem` 会分别统计整棵子树，汇总求和会重复。计划阶段应按条目粒度处理，并对 red 子路径做排除；这是 T09 的职责，T08 只报事实。
4. **`psutil` 为可选依赖**：缺失时 Windows 走 `tasklist`、macOS/Linux 走 `ps`，只能按名称匹配、无 `exe`；本机未覆盖无 psutil 的回退分支，建议打包时固定 psutil 版本并做一次无 psutil 冒烟测试。
5. **macOS/Linux 适配层未在真机验证**：代码已按 `ps` 回退实现，但本期验收环境为 Windows；catalog 路径本身也是 Windows 形态，跨平台启用前需 T03 补充对应 catalog。
6. **文件系统竞态**：扫描是快照，统计期间新增/删除文件会产生 warning 或轻微偏差；T09 计划阶段必须重新校验（架构 §4.2 已规定）。
7. **权限不足时大小偏小**：`access_errors > 0` 表示字节数可能不完整，计划层应据此提示用户，而不是静默迁移。
