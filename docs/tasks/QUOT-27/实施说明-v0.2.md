### 4. §10 阻塞态

- 580 档；头部「无法开始迁移」/「Cannot start migration」，`.sub` = `blocked.hint`。
- 行：44 高、`#fdf7f7` 底、`#f2c9c6` 边、左侧 3px 红条、18px 进程图标 + 名称 14/600 + PID 12 Consolas。
- 组标题「占用中的进程」13/700 + 3×14 绿条。
- `重新检测`：点击立即进入 loading，按钮宽度锁定为点击前 `min-width`，spinner 14×14 + 「检测中…」，`aria-disabled`；列表 `opacity:.6`。
- 检测期间 ESC / 遮罩 / `×` 均不可关窗（`closeModal()` 在 busy 时直接返回，`closeable=false`）。
- 仍阻塞：同弹窗就地重绘，消失行 300ms 淡出、保留行 400ms 红条闪一次，`blocked.stillBlocked` 计数行，滚动位置保留。
- 已解除：`.banner.ok` 停 300ms 后自动关窗 + 成功 toast。
- 失败：保留列表，上方 `.banner.danger` + 错误码 `.tl-code`，`.sub` = `blocked.recheckFailed`。
- >8s：恢复按钮 + `.banner.warn` + `blocked.recheckTimeout`，迟到的结果丢弃。
- 重新检测复用现有 `scan.result`（见决策记录），不新增 RPC。
- `prefers-reduced-motion` 下 spinner 为静态半环；弹窗打开聚焦首个可用控件，关闭后焦点回到触发入口。

## 二、数据缺口与偏差（需后端/设计师确认）

1. **无进程占用体积**：`runtime.running` 只有 `{name,pid}`，§10.1 的右侧体积列未实现，行内只保留名称 + PID。
2. **无专用重检 RPC**：用 `scan.result` 全量刷新后重读 `runtime.running` 判断是否解除；不新增 26 个方法之外的接口。
3. **本分支无法端到端运行**：仓库当前没有 `src/app/*` RPC host（pywebview 入口 / JSON-RPC 分发），只有 `ui/index.html` 与 `src/core`、`src/platform`。因此本轮只做了静态校验（脚本语法、i18n 键对齐、逐项对照文档），未做真机点击验收。
4. **历史字段映射缺口**：`src/core/store/history.py` 输出 `time/type/tool/item/source/target/bytes/result/stage/reason`，UI 需要 `at/app/from/to/freed/duration_seconds/code/can_rollback`；结果字面量 `success/failure/cancelled/rolled_back` vs UI 的 `failed/rolledback`。当前 UI 保留了兼容读取，但未在 host 层落地映射。
5. **已学习规则无时间戳**、冲突告警是扁平字符串、无 `rules.override.remove`——列表的排序/撤销/按来源筛选按现有字段降级。
6. **§12 其他未落地项**（撤销语义、项目零值显示等）沿用设计师文档中的降级口径，未擅自新增接口。
