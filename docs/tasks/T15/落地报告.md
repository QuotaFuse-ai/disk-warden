## 3. 功能落地

### 3.1 托盘

- 关闭窗口 → `on_closing` 返回 False，隐藏到托盘，进程不退。
- 托盘菜单：显示、隐藏、打开日志目录、退出；退出走 `quit_app()`，`window.destroy()` 后 `webview.start` 返回，进程结束。
- `--tray` / `--hidden` 启动即隐藏到托盘（自启使用 `--tray`）。
- 托盘图标起不来时降级：关闭窗口正常退出，不阻塞使用。

### 3.2 开机自启

- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` → `DiskWarden = "<exe>" --tray`。
- 仅当前用户可写，不触发 UAC；源码运行（未冻结）故意不注册，避免改到开发机真实启动项。
- `is_enabled` 用完整命令行比较，旧解压目录残留的路径不会显示成「已开启」。
- 关闭开关删除该值。

### 3.3 日志

- `app.log`：`RotatingFileHandler`，2 MB × 3；当天 JSONL 归档 14 天。
- `launcher.log`：启动器自身日志，2 MB × 3（启动器阶段主程序日志还没就绪）。
- 设置页「日志目录」调用 `App.openPath(settings.logsDir)`。
- 日志不含明文 Key；设置接口只返回 `api_key_set` / `api_key_source`。

## 5. 本轮修复

1. **恢复成功的判定缺陷（产品问题）**：`service._recover_worker` 直接把 `completion.ok` 当恢复结果，而回滚式恢复的 `completion.ok` 为 False，UI 会显示「恢复失败」，尽管数据已完整还原。改为 `ok = completion.ok or completion.rolled_back or state in (ROLLED_BACK, ALREADY_ROLLED_BACK)`，并加回归测试。
2. **沙箱演练被真实进程守护拦截（仅测试）**：构建机长期运行 Cursor，真实 catalog 会判定 `Cursor.exe` 在运行并拒绝迁移。`drill.py` 生成沙箱专用 catalog（进程名改为永不运行的占位符），只影响演练，不影响产品行为。
3. **残留进程误判（仅测试）**：`run-drills.ps1` 原先按进程名判断，把机器上另一个 `DiskWarden.exe` 当成残留；改为按 `ExecutablePath` 精确匹配本包。
4. **首启文案入包**：`build.ps1` 把 `START-HERE.txt` 一并压入 zip 根目录；文件名用 ASCII，避免 `Compress-Archive` 在非 UTF-8 文件名下的解压乱码。

## 6. 已知限制与风险

- **未签名**：首次运行会触发 SmartScreen，必须手动「更多信息 → 仍要运行」；企业环境可能直接拦截。签名证书属后续预算项（决策 0008）。
- **低完整性进程下仍会 WinError 5**：修复 `7cd8e95` 尚未合入 `integration/main`。当前验收在中等完整性目录 `C:\DiskWardenSandbox` 完成；若从低完整性进程（如沙箱化终端）启动，`mklink /J` 仍可能失败。合入后需复测。
- **平台范围**：仅 Windows 10/11 x64；macOS 打包与 Gatekeeper 引导归 T21。
- **IDE 覆盖**：本版实测 Cursor、Trae、Claude Code 三个目录布局；其余 IDE 由 catalog/规则覆盖，未经真机验证。
- **WebView2 依赖**：干净系统缺 WebView2 时无法显示界面，`START-HERE.txt` 已给出安装指引。
- **迁移依赖进程守护**：迁移/回滚前必须完全退出对应 IDE，这是数据保护设计，不是缺陷。

## 7. 复现步骤

```powershell
# 1. 构建（需要 Python 3.12 + packaging/requirements-build.txt）
powershell -ExecutionPolicy Bypass -File packaging/build.ps1 -Python <python.exe>

# 2. 打包产物验收（自动清理自启注册表值）
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/run-drills.ps1 -Sandbox C:\DiskWardenSandbox\accept

# 3. 单元测试
python -m unittest discover -s tests -q
```

演练只操作 `-Sandbox` 下的临时目录，不触碰真实用户数据。

## 8. 结论

T15 的功能与验收项全部落地：打包产物可双击运行、托盘可显示/隐藏/退出且无残留进程、自启写当前用户注册表无需管理员、日志按大小与日期轮转且可从设置打开、产物无明文密钥与调试符号。打包后的 exe 本身已在沙箱跑通「扫描 → 迁移 → 校验 → 回滚」与两种强杀点（复制中、改名后）的重启恢复，与 T13 源码级结论一致。
