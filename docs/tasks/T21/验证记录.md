## 3. 迁移 / 回滚 / 零数据丢失演练

演练脚本在本机系统临时目录建沙箱，跑**真实**文件复制与建链（不是内存 fake）：

```
python tools/migrate_drill.py      # 迁移主链路，robocopy 真实适配器
python tools/migrate_drill_b.py    # 中断与失败恢复
```

两次退出码均为 `0`，各场景结果：

| 场景 | 脚本 | 结果 | 数据安全证据 |
|---|---|---|---|
| 正常迁移 | `migrate_drill.py` / `drills/success` | `ok=true` | 源目录内容保持不变，目标校验通过后建链 |
| 校验不一致 | `drills/verify_mismatch` | `ok=false`，`VERIFY_FAILED` | `source_untouched=true`、`backup_kept=true`、`staging_removed=true`（1572864 vs 1572880 字节被识破） |
| 复制失败 | `drills/robocopy_bad_exit` | `ok=false`，`COPY_FAILED` | 真实 robocopy 退出码 ≥ 8 被映射，源未动 |
| 建链后崩溃 | `migrate_drill_b.py` / `drills/crash_after_link` | `ok=true` | 重启后自动收敛，回滚移除已提升的目标、清理 staging 与墓碑 |
| 建链前崩溃 | `drills/crash_before_link` | `ok=true` | 重启后识别为未完成迁移，源完整 |
| 建链失败 | `drills/link_failure` | `ok=false`，`LINK_FAILED` | 失败即回滚，源未动 |

回滚引擎本身由 `tests/test_rollback_engine.py`、`test_rollback_config.py`、`test_rollback_recovery.py` 覆盖（预检、逐步恢复、再次链接、恢复目录清理、内容比对）；「删链接不碰目标」在 `test_mac_link.py` 与 Windows 侧 `test_win_link_support.py` 双向固定。

**限制**：以上是 Windows 主机上的引擎证据。macOS 的 `rsync` / `ln -s` / `statfs` 分支是纯逻辑单测 + CI 冒烟，尚未在 Mac 上跑过一次真实迁移。这一点在第 6 节交给人类补齐。

### 5.3 已知缺口：macOS 扫描层

`data/ide-catalog.json` 顶层与全部 30 个工具条目的 `platform` 都是 `"windows"`，`src/core/scan/discovery.py` 用 `ntpath.splitdrive/join/normpath` 解析 `%APPDATA%\...` 模板。因此在 Mac 上：

- 自动扫描结果为空（没有匹配的目录清单）；
- UI 目前只有「扫描」一个入口，没有手动添加目录的界面，所以 0.9.0-beta 的 macOS 版**能启动、托盘/自启/日志/迁移引擎都就绪，但用户拿不到可迁移的条目**；
- 迁移 / 回滚 / 建链 / 删链这些链路本身与平台无关（平台层 + `posixpath` 已验证），缺的只是「发现」这一环。

本次没有伪造一份 macOS 清单来让测试"看起来绿"：`test_scan_discovery.py` 的相关用例按 `skipUnless(os.name == "nt")` 跳过，注释写明原因。`packaging/START-HERE-macOS.txt` 已写明该限制，避免用户把「列表为空」当成安装失败。补齐 macOS 目录清单与 `posixpath` 解析是独立任务，需要真实 Mac 的实测路径（`~/Library/Application Support`、`~/Library/Caches`、`~/.config` 等）。

### 5.4 一处观测，不影响行为

`smoke.json` 里 `link_support` 在 APFS 上返回 `supported=true` 同时仍带着 `code="TARGET_FS_UNSUPPORTED"`：`src/platform/mac/link.py` 的 `link_support()` 无论支持与否都填了 `code`/`message`（Windows 适配器同样如此）。业务层只在 `supported` 为假时才读 `code`（`src/app/service.py:1458`），所以没有任何误报或误拦截，只是日志字段不够干净。没有为此改代码再跑一次构建，以免已验收的 artifact 与 HEAD 脱节；如后续清理，三处适配器应统一成「支持时 `code`/`message` 为空」。

## 6. 必须由人类在 Mac 上补的一次点击验证

> 命令行能证明的东西到此为止。以下步骤需要一台 macOS 11+ Apple Silicon 或任意 Mac，约 10 分钟。

准备：取 CI artifact 的 zip（或 `packaging/build-macos.sh` 在 Mac 上产出的 zip）。

1. **解压**：双击 zip，确认 `DiskWarden.app` 与 `START-HERE-macOS.txt` 同在解压目录，`Contents/MacOS/DiskWarden` 有可执行权限。
2. **首启（macOS 15+）**：双击 → 弹「无法验证开发者」→ 关闭 → 系统设置 → 隐私与安全性 → 安全 → 「仍要打开」→ 认证 → 再确认。确认**右键打开已无效**。
3. **首启（Ventura ~ Sonoma）**：Control 点按图标 → 打开 → 「打开」。确认引导文案与实际系统一致（对比 `START-HERE-macOS.txt`）。
4. **应用内弹窗**：进入主界面后首启弹窗自动出现，步骤与系统版本匹配；点「我知道了」后不再自动弹，设置页可重开。
5. **迁移一次**：选一个可丢弃的 IDE 缓存目录，迁到另一块 APFS/HFS+ 卷；确认原路径变成 symlink（`ls -l` 显示 `->`）、IDE 能正常读写、`~/Library/Application Support/DiskWarden/logs/app.log` 有记录。
6. **回滚一次**：对该条记录点回滚，确认原目录恢复为实体目录、symlink 消失、文件数/大小与迁移前一致。
7. **删链接验安全**：对一个已迁移条目的链接执行删除，确认目标目录内容不受影响。
8. **托盘与自启**：关窗口后托盘存活、菜单可退出；设置里打开「开机启动」，注销后重新登录确认出现。关闭后 `~/Library/LaunchAgents/com.quotafuse.diskwarden.plist` 消失。
9. **异常路径**：迁移中拔盘/取消、目标卷只读、空间不足各试一次，确认提示清晰且源数据完好。

回填方式（第 5 节已完成，第 6 节待人类执行）：在第 6 节补「日期 / 截图或口头结论」，并把结论同步到 `docs/tasks/T21/落地报告.md` 第 4 节。
