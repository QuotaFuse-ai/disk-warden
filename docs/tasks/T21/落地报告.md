## 2. 平台层做了什么

### 2.1 卷信息与卷识别

- `volume_info(path)` 用 `statfs(2)` 取挂载点与文件系统名，设备身份用 `st_dev`。
- 之前的 POSIX 兜底把每个挂载点都写成 `/`，`same_volume` 会把两块盘判成同一块，swap 阶段可能跨卷 rename；macOS 实现修正了这一点。
- 目标卷必须是 APFS/HFS+（能存 symlink）；exFAT/FAT 在预检阶段直接报 `TARGET_FS_UNSUPPORTED`，不搬数据。

### 2.2 搬运

- `rsync -a --numeric-ids <src>/ <staging>/`：与 `robocopy src dst /E` 同语义，搬运目录内容。
- rsync 的 24（文件在传输中消失）按成功处理，完整性由读回校验负责；其余非零码映射为 `max(code, 8)`，业务层的退出码规则不变。
- 不带 `--delete`，不会删目标；`-a` 把 symlink 当 symlink 复制。
- 取消通过轮询 token 后终止子进程，错误码 `CANCELLED`。

### 2.3 建链、识别与删除

- `create_junction` 在 macOS 上执行 `ln -s`（不经 shell，参数逐个传递）。
- 建链后立即 `readlink` 读回并与期望目标比较；不一致则删除链接并抛 `LinkError`。
- `is_link` / `is_junction` 用 `lstat` + `S_ISLNK`，不跟随链接。
- 删除链接用 `os.unlink(link_path)`，绝不递归进目标目录；测试覆盖「删链接后目标内容不变」。
- `rename_dir` 用 `os.rename`，同卷内原子。

### 2.4 进程检测

- IDE 退出检测沿用通用 `ProcessInfo`；macOS 上的进程名不带 `.exe`，扫描层已有归一化逻辑。

### 2.5 开机自启

- 写当前用户 LaunchAgent，不需要管理员权限，不碰系统全局目录。
- `ProgramArguments` 用 `/usr/bin/open -n "<bundle>" --args --tray`：让 LaunchServices 启动 bundle，保留应用身份（图标、Dock、激活）。
- `KeepAlive=false`，崩溃不会变成两个托盘图标的循环重启。
- plist 用 `plistlib` 写临时文件后 `os.replace` 原子替换；关闭开关删除文件。
- 与 Windows 的 Run 键一致：下次登录生效，UI 明确说明。

### 2.6 首次启动引导（按系统版本）

`first_launch_guide()` 返回纯数据，页面只按 id 取文案：

| 字段 | 含义 |
|---|---|
| `tier` | `settings_pane`（15+）、`right_click`（11–14）、`unknown`、非 macOS 为 `none` |
| `steps` | 有序步骤 id；页面映射到 `firstRun.step.*` 文案 |
| `advanced_command` | `xattr -dr com.apple.quarantine '<bundle>'`，只放在折叠项里 |
| `show` | 未确认过首启时为 true |
| `supported` | 低于 macOS 11 为 false |

- macOS 15（Sequoia）+：系统设置 → 隐私与安全性 → 仍要打开；文案明确「右键打开已不可用」。
- Ventura ~ Sonoma：Control 点按 → 打开 → 再次确认。
- 版本探测失败时按 15+ 展示，并额外提示「看不到仍要打开就用 Control 点按」。
- 用户点「我知道了」写 `first_run_done=true`；设置页可随时重开。
- `xattr` 命令仅为折叠高级项，旁边写明风险：去掉整个 App 的来源标记，且不能替代签名。

### 2.7 数据与日志位置

- 数据根：`~/Library/Application Support/DiskWarden`。
- 日志：`<数据根>/logs/app.log`，2 MB × 3 轮转 + 按天 JSONL 保留 14 天（与 Windows 共用实现）。
- 托盘使用 pystray 的 `_darwin` 后端；关闭窗口隐藏，菜单栏退出。

## 3. CI 构建

| 步骤 | 内容 |
|---|---|
| Runner | `macos-latest`（Apple Silicon，arm64） |
| Python | 3.12 + `packaging/requirements-build-macos.txt` |
| 单元测试 | `pytest tests -q`（`continue-on-error`，失败不阻止产物流出，但最终让 job 变红） |
| 图标 | `make_icns.py` 由 `packaging/DiskWarden.ico` 生成 `.icns` |
| 打包 | PyInstaller `DiskWarden-macos.spec` → `dist/DiskWarden.app` |
| 结构检查 | 可执行文件存在、`plutil` 校验 Info.plist、Bundle ID、`ui/index.html` 与 assets 在包内 |
| 冒烟 | `DiskWarden --smoke --smoke-out smoke.json`：冻结态、`cocoa` 后端、UI 存在、托盘可用、数据根可写、link 支持 |
| 压缩 | `ditto -c -k --keepParent`（保留 symlink、权限、扩展属性），zip 根目录含 `START-HERE-macOS.txt` |
| 产物 | `DiskWarden-macos-arm64-unsigned`：zip、sha256、smoke.json，保留 30 天 |
| 触发 | `workflow_dispatch`；合并到 `main` 或向 `main` 提 PR 且命中 `src/**`、`tests/**`、`packaging/**`、`ui/**`、`data/**` 时也触发（PR 事件让分支先拿到一次真实构建） |

选择 `ditto` 而不是 `zip(1)`：后者会丢 symlink 和权限位，解压后的 `.app` 起不来。zip 里额外校验 `START-HERE-macOS.txt` 存在。

## 6. 明确不做（本期）

- **代码签名与公证**：需要 Apple Developer 账号与费用，由人类决策；本期只保证未签名包可用且有清晰引导。
- **Intel (x64) 构建**：`macos-latest` 是 arm64；需要时加 `macos-13` 矩阵腿。
- **通用二进制 / universal2**：同上，未排期。

## 7. 风险与后续

| 风险 | 处理 |
|---|---|
| 无 Mac 真机点击验证 | CI 冒烟 + artifact 证据先行；发布前必须由人类在任意 Mac 上走一遍（见验证记录） |
| Gatekeeper 文案随系统更新变化 | 版本探测与步骤分层，文案集中在一处，改动成本低 |
| rsync 在极老系统缺失 | macOS 自带 `/usr/bin/rsync`；失败时 `TransferError` 明确报错 |
| 未签名包被误判为恶意软件 | `START-HERE-macOS.txt` 与首启弹窗都说明来源与原因；长期靠签名解决 |
| macOS 自动扫描为空（清单仍是 Windows 专用） | 已标注为后续任务；`packaging/START-HERE-macOS.txt` 明确写了「扫描结果为 0 是预期行为」，避免用户当成安装失败 |
