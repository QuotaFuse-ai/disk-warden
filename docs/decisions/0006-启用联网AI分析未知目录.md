# 决策 0006：接受联网 AI 分析未知目录，并实现该功能接口

- 日期：2026-10-19
- 决策人：项目领导人（依据人类在 QUOT-2 的指示）
- 状态：已生效，替代决策 0001 中"不做第三层 AI 分析"的表述

## 背景

决策 0001 与 `任务拆解清单` 原先规定：第三层 AI 分析只保留接口，不做联网实现，理由是费用与隐私未确认（R6）。人类在 QUOT-2 明确答复：接受联网 AI 分析未知目录，并要求实现该功能接口。

## 决策

1. **启用第三层联网 AI 分析**，但只作用于规则引擎判为**黄色（未知）**的目录。绿色/红色结论不送 AI，AI 也不能推翻目录表与模式规则的红色终态。
2. **AI 结论一律 `requires_confirm=true`**：只作为"建议 + 理由"展示，必须用户逐项确认后才能进入迁移，不参与自动迁移。
3. **隐私边界（硬约束）**：
   - 只发送目录的相对路径片段、层级、文件数、总大小、文件类型分布等元数据；
   - **不发送文件内容、文件名以外的用户数据、绝对路径中的用户名、环境变量值**；
   - 发送前统一做路径脱敏（去掉盘符/家目录/用户名）。
4. **默认关闭、显式开启**：设置项关闭时完全不联网；开启时界面明确提示"目录信息将发送到第三方 AI 服务"。
5. **成本可控**：按目录做结果缓存（键 = 脱敏路径 + 规则版本 + 提示词版本）；单次扫描设 token/调用次数上限；超限或网络失败时静默降级为黄色，不阻塞扫描。
6. **供应商无关**：实现 OpenAI 兼容的 HTTP 适配器，endpoint / model / api_key 由设置或环境变量注入；不在仓库写入任何密钥；未配置密钥时功能保持关闭。
7. **实现范围**：本期交付 `src/core/ai/`（接口、适配器、提示词、缓存、脱敏、错误处理）+ 注入到现有 `AIResolver` 钩子 + CLI `--ai` 开关 + 假传输单测。真实联网验证需人类提供可用的 endpoint / model / key，并确认费用上限。
8. **排期**：新增 T22（后端架构师，2d），与阶段 2 并行；P0 主链路（T09–T12）优先级高于 T22，工时冲突时 T22 让路。

## 影响

- `任务拆解清单` 的"明确不做"删除"AI 联网实现"条目，新增 T22。
- `派活清单` 的 D3 置为"已确认（本决策）"，新增 QUOT-21。
- 不需要新增付费依赖；是否产生 AI 调用费用取决于人类提供的供应商与额度。
- 隐私说明需在 T12 主界面与 T21 首次启动文档中同步体现。
