# 决策 0001：第一期范围与优先级

- 日期：2026-10-18
- 决策人：项目领导人
- 状态：已生效

## 背景

`docs/功能需求.md` v0.1 列了 8 个功能模块，但没有排优先级。团队 12 人同时开工会导致资源分散，且迁移功能是破坏性操作，必须先有安全闭环。

## 决策

1. **第一期（P0）只做一条主链路**：扫描 → 规则判定 → 迁移 → 备份 → 校验 → 建 junction → 验证 → 回滚。其余模块一律不进 P0。
2. **P0 的功能范围**：
   - 第一层硬编码识别 + 第二层规则引擎（不做第三层 AI 分析）
   - 已知 IDE 的 exhaust/state 分类（基于 `docs/目录清单.md`）
   - 单目录/多目录迁移，目标盘选择，空间预检
   - 配置备份、robocopy 搬运、校验、删源、`mklink /J`、迁移后验证
   - 一键回滚 + 配置恢复
   - 进程占用检测与拦截
   - 本地 settings / rules-learned / history
   - 主界面（IDE 数据页）接真实数据
3. **P1**：项目目录、C 盘全景、规则学习页、操作历史页、打包 exe + 托盘、欢迎页/OAuth/Star、官网。
4. **P2**：云端规则同步、CI、Mac 版、自动更新。
5. **降级原则**：工期冲突时，界面表现力让位于数据正确性与可回滚性；任何"顺手多做"的需求必须先落进本清单再排期。

## 影响

- 阶段 1 的 5 个任务全部为栈无关产出，不因技术选型未定而返工。
- 阶段 2 只围绕 `src/scan`、`src/rules`、`src/migrate`、`src/rollback`、`src/store` 五个模块展开。
- 个人端/支付/论坛/数据分析相关的小队能力本期不启用。
