## 问题

项目里存在两套互相冲突的技术栈描述：

| 来源 | 描述 |
|---|---|
| `docs/功能需求.md` 第 4 章 | Python 3.12 + 现有 HTML/原生 JS + PyInstaller 内嵌 webview；Windows 先行 |
| 团队/项目背景说明 | React + Electron 桌面应用，官网 + 主机端（hub）+ 个人端（dsk） |

现有代码也自相矛盾：`main.py` 用 Tkinter，`ui/index.html` 是浏览器原型，两者没有接线。

## 两个候选方案

| 维度 | A：Python 核心 + pywebview/PyInstaller | B：Electron + React |
|---|---|---|
| 与现有文档一致性 | 高（需求文档就是这样定的） | 低（需重写需求第 4 章） |
| 系统能力（扫描/robocopy/mklink） | 原生 Python，直接调 Win32，进程/权限控制简单 | 需 Node 调用或调 Python 子进程，多一层 |
| 包体积 | 约 15~30 MB | 约 80~150 MB |
| 前端开发效率 | 原生 JS，无构建链，复杂交互维护成本高 | 组件化、状态管理、生态成熟 |
| 跨平台 | Windows 优先，Mac 需要分平台命令 | 跨平台一致性更好 |
| 团队匹配度 | 后端/主机端偏 Python，前端偏 React | 团队当前配置更偏 React/Electron |
| 安全面 | 本地单进程，攻击面小 | 需注意 renderer 隔离、IPC 权限 |
