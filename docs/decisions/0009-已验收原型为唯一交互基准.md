# 0009 已验收原型为唯一交互基准，T12 接线需回放

- 日期：2026-10-19
- 状态：已生效
- 决策人：项目领导人
- 相关任务：T04（QUOT-6）、T12（QUOT-14）

## 背景

T04 的 `ui/index.html` 在用户评审后经过三轮改动并被验收：

- `906a3f0` AI 识别入口、固定外壳与分区内滚动、规则按软件分组；
- `d04bb92` C 盘全景与规则学习改为两列；
- `2ffe7b4` 规则学习去卡片框、按软件规则弹窗（`#rules-app/<id>`）。

T12 并行开发，其分支 `agent/agent/3785a5d5b0d0` 基于另一个仓库的公开快照 `7c51d10`，该快照的 `ui/index.html` 与上述三轮改动之前一致。因此 T12 分支的界面缺少规则弹窗、AI 识别入口、分组行等结构（实测：T12 分支无 `rules-app` / `AI 识别` / `appgrp` 标记，i18n 573 key；已验收版本 585 key、19 条 hash 路由）。

两者所在仓库历史不相交（公开仓库为 `2d2e630 feat: initial public release` 的压缩历史），无法直接 `git merge`。

## 决策

1. **`ui/index.html` 以当前开发仓 main（`2ffe7b4`）为唯一交互基准。** 任何接入真实数据的改动都必须回放到该版本上，不得用旧文件覆盖。
2. T12 的接线工作以「回放」方式合入：新建分支（基于 `2ffe7b4`），逐块把桥接调用、真实数据、事件订阅接到已验收结构上。冲突一律以已验收原型为准（样式、文案、路由、弹窗、字号阶梯）。
3. T12 的 `src/app` 桥接层、`src/app` 测试、`src/core` 相关改动可直接沿用，不重写。
4. `main.py` 存在两套入口（开发仓的 tkinter 欢迎页、T12 的 pywebview 入口），本轮先并存，由 T15（打包/托盘/自启）与 T16（欢迎页）统一，不在接线任务里删除现有入口。
5. T04 验收时记录的 4 条「锦上添花」小项（规则表单与表格栅格对齐、三个操作按钮等权重、时间线占位数据重复、反馈入口两处重复）暂不处理，待 T12 回放完成后统一排期。

## 验收口径

- `ui/index.html` 与 `2ffe7b4` 的差异只包含接线代码，界面结构、文案、字号无回退；
- 585 个中英文 key 对齐、19 条 hash 路由保留；
- 软件规则弹窗与左列双向同步在接入真实数据后仍成立；
- 无头浏览器 19 路由 × 3 种窗口：0 JS 报错、0 横向溢出、页面自身不滚动。

## 影响

- T12 的 PR 在回放完成前不得合并；
- 后续所有界面改动以开发仓 main 为准，公开仓库只做发布快照。
