# 决策 0008：首期双平台不签名交付，配套首次启动引导

- 日期：2026-10-19
- 决策人：项目领导人（依据人类在 QUOT-2 的指示）
- 状态：已生效，补充决策 0005 与 0007

## 背景

人类在 QUOT-2 明确：不签名也能出包，T21 会配首次启动引导。此前 D4 只把签名/公证列为"后续再定"，未明确首期是否接受未签名产物。本决策把"首期不签名"定下来。

## 决策

1. **首期（P0）Windows 与 macOS 均交付未签名包**，不为签名/公证阻塞发布。
2. **macOS**：T21 负责按系统版本提供首次启动引导（设置 → 隐私与安全性 → 仍要打开；Ventura–Sonoma 右键打开；终端命令仅作高级折叠项并注明风险），文案同时进入 README/下载页与应用内首启弹窗。
3. **Windows**：T15 负责补充 SmartScreen 引导（"更多信息 → 仍要运行"），文案进入下载页与安装包首启提示；不引导用户关闭系统安全功能。
4. **不做的事**：不伪造签名、不诱导用户全局关闭 Gatekeeper/SmartScreen、不把"绕过安全提示"包装成无风险操作。
5. **后续**：若获得预算，再按新决策采购 Windows 代码签名证书与 Apple Developer 账号；届时首启引导保留作为兜底。
6. **验收口径**：未签名产物在干净环境可安装/启动；首启引导步骤与实际系统版本一致；不出现"跳过安全检查"类文案。

## 影响

- `任务拆解清单` T15 交付物增加 Windows SmartScreen 引导；T21 维持 macOS 引导。
- `派活清单` D4 置为"已确认：首期不签名"；签名预算转为后续可选项，不再阻塞。
- 风险：未签名包会触发系统警告，部分企业环境可能直接拦截；用户信任成本由首启引导与官网说明承担。官网本期不做，说明放在 README 与发布页。
