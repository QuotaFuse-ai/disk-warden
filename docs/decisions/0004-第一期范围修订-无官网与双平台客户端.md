# 决策 0004：第一期范围修订（无官网、双平台客户端）

- 日期：2026-10-19
- 决策人：项目领导人（依人类指示）
- 状态：已生效
- 关联：`docs/decisions/0001-第一期范围与优先级.md`、`docs/decisions/0003-运行时外壳最终选型.md`
- 任务：QUOT-2

## 1. 人类指示原文

> 没有官网，这个是quotafuse平台的子项目，后续可能有官网，前期只有win、mac的客户端应用产品

## 2. 决策

1. **第一期不做官网。** 原 T17（官网落地页）撤销，Multica 单 QUOT-19 置 `cancelled`。官网属于"后续可能"，需要时另立任务，不影响本期排期。
2. **disk-warden 是 quotafuse 平台的子项目。** 不做独立的三端叙事（官网 + 主机端 hub + 个人端 dsk）；本期只有客户端应用，不做账号系统、云同步、支付、论坛。
3. **第一期客户端覆盖 Windows 与 macOS。** macOS 从决策 0001 的 P2 提升为第一期交付物（P1 序列），与 Windows 同属产品范围。
4. **P0 验收口径不变。** P0 主链路仍先在 Windows 跑通并完成沙箱闭环（扫描 → 迁移 → 验证 → 回滚，数据零丢失）；macOS 适配紧随 Windows 闭环之后，不降低 P0 的安全与校验标准。

## 3. 与既有决策的关系

- 决策 0001 不修改（只增不改）。本文件仅覆盖其中两处：第 3 条 P1 中的"官网"作废；第 4 条 P2 中的"Mac 版"提升为第一期。
- 决策 0003 的待确认项 2（单机工具 + 官网 vs hub/dsk 三端）由此得到答复：两者都不是，本期为**单机双平台客户端**。决策 0003 的待确认项 1（技术栈 A/B）仍未答复，阶段 2 继续冻结。
- 决策 0002 保持原状。

## 4. 影响

1. **架构要求**：Windows 专有调用（robocopy、`mklink /J`、卷信息、进程、长路径）必须全部收敛到 `src/platform/`，业务层不得直接调用；macOS 侧实现同一接口（`rsync`/`cp` 搬运、`ln -s` 建链、卷与进程查询）。
2. **任务调整**：
   - T08 进程占用检测需平台无关，Windows 侧判断独占句柄/进程名，macOS 侧至少判断进程名。
   - T09 搬运与校验走平台适配层；T10 建链与回滚在 macOS 侧验证符号链接语义与删除安全性。
   - T13 增加 macOS 用例；T15 打包扩展为双平台产物。
   - 新立 T21：macOS 平台适配与打包（2d，运维工程师）。
3. **人类依赖新增**：macOS 构建与分发需要一台 macOS 构建机；若要消除 Gatekeeper 警告，还需 Apple Developer 账号与公证费用。这与决策 0003 待确认项 8（Windows 代码签名）合并为同一类"签名/公证成本"决策，由人类拍板。
4. **团队**：官网开发小队本期不派活。
