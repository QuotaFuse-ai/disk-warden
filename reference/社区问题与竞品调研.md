## 三、竞品分析

### 3.1 CleanMyDev（Mac，$9.99买断）

| 项目 | 内容 |
|---|---|
| 做什么 | 扫描AI工具目录 → 删到废纸篓 |
| 覆盖 | 8个工具，110+条路径 |
| 做不做迁移 | **不做，只删** |
| 平台 | 仅Mac |
| 价格 | $9.99买断 |
| 跟咱们区别 | 它删完还会涨回来；咱们junction后新数据自动落D盘 |
| 可复用 | 它的路径分类表（exhaust可删/state不动）咱们直接复用 |

### 3.2 Symlinker（GitHub 508 stars）

| 项目 | 内容 |
|---|---|
| 做什么 | 通用junction创建工具 |
| 认识IDE目录吗 | **不认识**，让用户自己选目录 |
| 做不做清理 | 不做 |
| 平台 | Windows |
| 跟咱们区别 | 它是通用工具不敢判断哪些目录能动；咱们认识IDE目录，自动标安全等级 |

| 工具 | 做什么 | 问题 |

### 3.4 为什么没人做专门的"AI IDE junction迁移"工具？

1. **通用工具不敢判断安全边界**——怕搬错了用户登录不了回来骂
2. **每个IDE目录结构不同**——要逐个研究，是脏活
3. **会被C盘逼到搜解决方案的人**，往往自己会敲mklink命令，不需要GUI
4. **需要GUI的小白用户**，根本不知道是Cursor吃了C盘

**这个位置是空的。**

## 四、已验证的技术方案

### 4.1 Windows junction

```
命令：mklink /J "C:\原路径" "D:\新路径"
- 不需要管理员权限
- 重启不断
- 应用完全无感知（透明重定向）
- 新数据自动写到目标盘
- 可一键回滚（删junction+搬回数据）
```

### 4.2 Mac symlink

```
命令：ln -s "/目标盘/IDEData/Cursor/Cache" "~/Library/Application Support/Cursor/Cache"
- 普通用户权限即可（用户目录下不需要sudo）
- 重启不断
- 同样透明
```

### 4.3 迁移流程

```
1. 检测IDE进程是否在运行（在运行就警告）
2. 备份settings.json等配置
3. robocopy 搬数据到目标盘
4. 验证数据搬完了
5. 删C盘原目录
6. mklink /J 建junction
7. 验证junction成功
```
